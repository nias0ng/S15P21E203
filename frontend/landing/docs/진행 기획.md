# 향을 찾는 종이배 — 진행 기획

작성 2026-08-30 · 파일 `향을 찾는 종이배.dc.html` (807줄, 단일 컴포넌트)

---

## 1. 컨셉

흰 여백 위를 종이배 한 척이 떠간다. 하늘도 지평선도 없고, 물은 배경색(`#F8F7F3`)으로 흩어져 사라진다.
사용자는 향을 검색하거나 직접 배를 몰아서, 물 위에 흩어진 네 개의 향 영역으로 접근한다.

- **바다** = 향의 지도. 좌표는 있지만 경계는 없다.
- **배** = 사용자의 시점. 카메라는 월드에 고정이고 도는 것은 배뿐이다.
- **항적** = 지나온 취향의 기록.

## 2. 현재 구현된 것

### 2.1 수면 — GPU 파동 시뮬레이션

노이즈가 아니라 실제 파동방정식을 핑퐁 렌더타깃으로 푼다.

| 항목 | 값 | 비고 |
|---|---|---|
| 격자 해상도 | 640² | RGBA half-float. x=높이, y=속도, z=항적 |
| 월드 도메인 | 110 × 110 | 배를 중심(`centerZ: 0`)에 둔다 |
| 타임스텝 | 고정 1/120s, 최대 8스텝 | 주사율과 무관하게 항상 같은 물 |
| 전파 계수 | 0.34 | 0.5 이상은 발산 |
| 감쇠 | 0.9975 | |

- **흡수층(sponge)** — 가장자리 58%부터 진폭을 깎아 파도가 도메인 벽에 반사되지 않는다.
- **이류(advection)** — 배가 나아간 만큼 높이맵 전체를 UV로 밀어, 물이 배를 지나 흘러간다.
- **선체 상호작용** — 파를 *더하지* 않고 흘수 깊이만큼 수면을 **붙잡는다**(`bowGrip 0.30`). 누적 발산이 없고, 흐름이 지나가면서 자연히 항적이 남는다.
- **상시 너울** — 0.025초마다 무작위 위치에 큰 교란을 뿌려 정지 상태에서도 물이 죽지 않는다.
- **긴 주기 너울** — 시뮬과 별개로 해석적 sin 조합(`swellH`)을 얹는다. 속도가 붙으면 진폭이 커진다.

### 2.2 명암

기하 변위는 0.35배로 얌전하게, 법선 배율은 40배로 따로 준다. 실루엣은 잔잔한데 음영은 또렷하다.
`base #FDFCF9` / `shade #BEB8A6` 두 색만 쓰고, 거리 30~50에서 배경색으로 용해된다.

### 2.3 등고선 그리드 — **3단 LOD (직전 작업)**

수면 바로 아래 깔리는 와이어프레임. 원래 2단이었고 링 경계가 눈에 보여서 다시 짰다.

| 준위 | 셀 | 크기/분할 | 페이드 인 | 페이드 아웃 |
|---|---|---|---|---|
| T0 | 0.4 | 40 / 100 | — | 9 → 20 |
| T1 | 0.8 | 84 / 105 | 9 → 20 | 24 → 40 |
| T2 | 1.6 | 168 / 105 | 24 → 40 | — |

- 셀 크기가 **정확히 2배씩** 커져 굵은 선의 격자가 항상 겹친다. 준위별 wrap(모듈로)을 따로 걸어도 서로 미끄러지지 않는다.
- 페이드 구간을 넓게 잡고 `sqrt`로 알파를 보정 — 겹치는 구간에서 선이 묽어지지 않는다.
- 파의 경사(`vSteep`)와 항적(`vTrail`)이 있는 곳에서 선이 짙어진다. 마루가 등고선처럼 드러난다.
- 원경은 변위를 접어 평평하게 만든다(지평선에 선이 뜨는 것 방지).

### 2.4 배와 조작

- 종이배는 `ExtrudeGeometry` 절차 생성. **`createBoat()` 내부만 바꾸면 GLB로 교체 가능**하게 격리해 뒀다.
- **부력** — 높이맵을 선체 길이/폭 방향 4점에서 읽어 pitch·roll·y를 실제 수면에 맞춘다. 아이들 모션은 그 위에 얹힌다.
- **조향** — 각속도 자체에 관성이 있다(`turnLerp 0.012`). 360도 열려 있고, 방향에 따라 x·z 양쪽으로 흐른다.
- 입력: 드래그 / ← → 방향, Shift 또는 휠↑ 가속. 하단 DRIFT 슬라이더가 현재 속도를 표시한다.

### 2.5 향 영역

| 영역 | 색 | 좌표 (x, z) | 키워드 |
|---|---|---|---|
| FLORAL | `#D9738F` | -22, -30 | 플로럴 / 꽃 / 장미 / rose |
| WOODY | `#5A8B6A` | 14, -42 | 우디 / 나무 / 숲 / 시더 |
| FRESH | `#7BA8C4` | -10, -56 | 프레시 / 상쾌 / 시트러스 / 바다 |
| SWEET | `#C9A227` | 30, -68 | 스위트 / 달콤 / 바닐라 |

- 반경 18의 점 구름 26개 + 수면 자체가 그 색으로 물든다.
- HTML 라벨을 3D 좌표에 투영해 따라다닌다.
- 검색어가 키워드에 맞으면 `this.auto`가 설정되고 **배가 스스로 그쪽으로 뱃머리를 돌린다**.
- 영역은 100 단위로 x·z 양방향 순환 — 어느 쪽으로 돌아도 다시 나타난다.

### 2.6 조절 가능한 값 (Tweaks)

수면 5종 · 배 2종 · 움직임 · 항적 · 향 영역 · 그리드 4종, 총 14개 prop.

## 3. 남은 작업

### 3.1 우선순위 높음

1. **도착 상태가 없다.** 지금은 영역 안에 들어가도 물 색만 변한다. 도착 판정 → 향 카드/노트 노출 → 다음 행동으로 이어지는 흐름이 필요하다.
2. **검색이 키워드 일치뿐이다.** 오타·자유문장("여름밤에 어울리는 거")이 안 걸린다. 유사도 매칭 또는 후보 제안이 필요하다.
3. **검색 실패 시 피드백이 없다.** 못 찾으면 아무 일도 일어나지 않는다.

### 3.2 우선순위 중간

4. **종이배 GLB 교체.** 현재 절차 생성 메시는 형태가 단순하다. `createBoat()` 교체 지점은 준비됨.
5. **모바일 입력.** 터치 드래그는 되지만 가속 수단이 없다.
6. **성능 확인.** 640² 시뮬 + 3단 와이어프레임의 저사양 GPU 프레임레이트를 재야 한다. 필요하면 해상도/준위 수를 디바이스별로 낮춘다.

### 3.3 열려 있는 질문

- 영역이 4개로 충분한가. 향 계열을 더 쪼갤 것인가.
- 항적이 실제로 무언가를 남겨야 하는가 (지나온 향의 기록으로 재방문 가능한지).
- 목적지 도착 후 카메라가 어떻게 바뀌어야 하는가 (배 시점 유지 / 상공 / 정지).
