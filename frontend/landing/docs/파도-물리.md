# 파도의 물리 — 무엇을 흉내 내고 있고, 무엇이 빠졌는가

> 2026-09-03. 사용자 문제 제기 : *"느린 파도가 있고 빠른 파도가 있고 그것들이 다시
> 합쳐졌다가 사라졌다가 하는 물리… 왜 파도가 생성되고 자연스러운 파도가 되는지
> 확인부터 해봐야겠는데. 단순 github 에 물리를 구현한걸 참고해서 진행하는 게 아니라."*

**이 문서가 하는 일** : 파도의 물리를 정리하고, 지금 `swell.js` 가 그중 무엇을 맞게
하고 있고 무엇을 놓치고 있는지를 **실측 수치로** 대조한 뒤, 다음 구현과 그 **검증 기준**을
정한다.

**이 문서가 하지 않는 일** : 코드를 고치지 않는다. 이 문서에 합의가 된 다음에 고친다.

**8장이 그 기각 기록이고, 지금 이 문서에서 가장 중요한 부분이다.**

## 1. 왜 파도가 생기는가

바람이 물을 미는 것만으로는 지금 같은 파도가 안 나온다. 세 단계를 거친다.

**① Phillips 공명 (1957) — 씨앗.**
바람은 매끈하게 불지 않는다. 난류라서 수면에 **압력의 얼룩**이 떠다니고, 그 얼룩이
움직이는 속도와 어떤 파장의 파가 나아가는 속도가 맞아떨어지면 공명이 일어난다.
에너지가 **시간에 비례해** 자란다 — 느리다. 잔물결이 여기서 태어난다.

**② Miles 불안정 (1957) — 증폭.**
일단 파가 생기면 그 위를 지나는 바람이 파의 모양 때문에 휘고, 마루 앞뒤로 압력차가
생겨 파를 더 민다. 파가 클수록 더 세게 밀리므로 에너지가 **지수로** 자란다. 대부분의
성장이 여기서 일어난다.

**③ 비선형 전달 (Hasselmann, 1962) — 재분배.**
파들끼리 에너지를 주고받는다 (네 파의 공명). 그 결과 에너지가 **더 긴 파장 쪽으로**
옮겨간다. 그래서 바다가 자랄수록 파장이 길어지고 첨두 주파수가 내려간다.

**한계를 정하는 것 둘.**
- **취송거리(fetch)** : 바람이 물 위를 얼마나 길게 부는가
- **지속시간** : 얼마나 오래 부는가

둘 중 하나가 모자라면 "덜 자란 바다"고, 둘 다 충분하면 **완전발달 해상(fully developed
sea)** 이다. 그때의 스펙트럼이 아래 Pierson-Moskowitz 다.

> **우리에게 주는 것** : 바람 시뮬은 필요 없다. 결과인 **스펙트럼**만 있으면 된다.
> 다만 "왜 여러 파장이 동시에 있는가"의 답이 여기 있다 — 한 파장만 있는 바다는 없다.

## 2. 파도가 움직이는 방식 — 분산관계

### 2-1. 심해 분산관계

수심이 파장의 절반보다 깊으면 (우리는 항상 그렇다) :

```
ω² = g·k          ω = 각속도,  k = 파수 = 2π/λ,  g = 9.81
```

여기서 **위상속도**(마루 하나가 나아가는 속도) :

```
c = ω/k = √(g/k) = √(gλ / 2π)
```

**긴 파가 빠르다.** 파장이 4배면 속도가 2배다. 이게 "느린 파도와 빠른 파도"의 정체다 —
파도마다 성격이 다른 게 아니라 **파장이 속도를 정한다.**

### 2-2. ⭐ 군속도 — "합쳐졌다 사라졌다"의 진짜 원인

여러 파가 겹치면 **덩어리(군, group)** 가 생긴다. 그 덩어리가 나아가는 속도는 마루가
나아가는 속도와 **다르다**.

```
cg = dω/dk = ½·√(g/k) = c / 2          ← 심해에서는 정확히 절반
```

**에너지는 마루의 절반 속도로 간다.** 그래서 실제 바다를 보면 :

> 덩어리 **뒤쪽에서 마루가 태어나** 덩어리를 앞질러 가로지르고,
> **앞쪽에 닿으면 사라진다.**

사용자가 본 "합쳐졌다가 사라졌다가" 가 정확히 이것이다. 개별 파도가 소멸하는 게 아니라,
**마루가 군을 통과하며 나타났다 없어지는 것처럼 보이는** 현상이다.

⚠ **이건 공짜로 나온다.** 분산관계 `ω ∝ √k` 만 지키면 자동으로 생긴다. 따로 구현할
현상이 아니다 — 오히려 ω 를 아무렇게나 정하면 **깨진다.**

### 2-3. 우리 구현 실측

10대역 전부에서 `ω/√k` 가 **1.9419 로 완전히 일정**하다. 즉 분산관계는 정확하다.

| 파장 | 주기 T | 위상속도 c | 군속도 cg |
|---|---|---|---|
| 16.0 | 5.16초 | 3.10 | 1.55 |
| 9.6 | 4.00초 | 2.40 | 1.20 |
| 5.60 | 3.05초 | 1.83 | 0.92 |
| 3.20 (주파) | 2.31초 | 1.39 | 0.69 |
| 1.60 | 1.63초 | 0.98 | 0.49 |

⚠ 실제 심해는 `ω = √(g·k)` 라 계수가 **√9.81 = 3.132** 여야 한다. 우리는 **1.9419**,
즉 **0.62배**다. 여기에 `params.waveSpeed` 0.48 이 또 곱해져 **최종 0.30배**로 흐른다.

**이건 버그가 아니라 의도된 양식화다.** 계수를 상수로 곱하면 c 와 cg 가 **같은 비율로**
느려지므로 `cg/c = 1/2` 는 그대로 지켜진다 — 군 현상은 온전하다. 다만 **바다의 스케일이
작아 보이는 원인**이기도 하다. 실제 파장 3.2m 짜리 파는 주기가 1.43초인데 우리는 2.31초로
흐른다. 느리게 흐르는 물은 크게 보인다.

## 3. 스펙트럼 — 에너지가 주파수에 어떻게 퍼지는가

### 3-1. Pierson-Moskowitz (완전발달)

```
S(ω) = α·g² / ω⁵ · exp( −β·(ω₀/ω)⁴ )          α ≈ 8.1e-3,  β = 0.74
```

핵심은 **고주파 쪽이 ω⁻⁵ 로 떨어진다**는 것. 짧은 파는 에너지가 급격히 적다.
그리고 첨두 주파수 아래로는 지수적으로 죽는다 — 아주 긴 파는 거의 없다.

### 3-2. JONSWAP (취송거리 제한)

북해 관측에서 나온 보정. PM 에 첨두 강조 인자를 곱한다 (γ ≈ 3.3).
**젊은 바다는 첨두가 더 뾰족하다** — 한 파장이 더 도드라진다.
우리 바다는 "배가 지나가는 잔잔한 해역"이므로 JONSWAP 쪽 성격이 맞다.

### 3-3. 방향 분산

에너지는 바람 방향에 몰려 있고 옆으로 퍼진다 :

```
D(θ) ∝ cos^{2s}(θ/2)      또는 간단히 cos²θ    (첨두 근처가 더 좁다)
```

대략 **±30° 안에 대부분**이 들어온다.

⚠ 이건 우리가 이미 지키고 있다. `swell.js` 주석 ① : 예전에 −69°~+115° 로 180° 넘게
퍼뜨렸다가 마루가 안 이어지고 **달걀판 격자**가 됐다는 기록이 있다. 지금은 −25°~−65°
(40° 폭). 실제 물리와 맞는 선택이다.

### 3-4. 파고의 통계 — 레일리 분포

수면 높이가 정규분포면 **파고는 레일리 분포**를 따른다.

```
유의파고 H_s = 4σ        (σ = 수면 높이의 표준편차)
H_max / H_s ≈ 1.86       (파 1000개를 볼 때)
```

⚠ 우리 코드의 `swellAmplitude()` 가 내는 `2σ` 는 **H_s / 2**, 즉 "눈에 보이는 마루 높이"다.
이름이 진폭이라 헷갈리기 쉽다.

**실측** : 우리 바다의 마루 높이는 최대/평균 **2.96**, 변동계수 **0.67**.
레일리 분포의 변동계수가 약 0.52 이니 오히려 **더 들쭉날쭉하다.** 이쪽은 문제가 아니다.

## 4. 군파 — 얼마나 뭉쳐 있는가

### 4-1. 왜 뭉치는가

가까운 두 주파수가 겹치면 **맥놀이**가 생긴다. 주파수 차가 작을수록 군이 길다.
실제 바다는 스펙트럼이 연속이라 군이 계속 만들어지고 부서진다.
(더 나아가 **Benjamin–Feir 불안정** — 파가 스스로 에너지를 뭉치는 비선형 현상이 있고,
이상파랑(freak wave)의 설명이다. 우리 규모에서는 안 다뤄도 된다.)

### 4-2. 재는 법 — 군집도 (Groupiness Factor)

한 점의 수면 높이 시계열에서 **포락선**(국소 RMS)을 뽑고 :

```
GF = std(포락선) / mean(포락선)
```

실제 바다는 **0.6 ~ 1.0**. 0 에 가까우면 "고른 파도"고, 크면 "세트로 몰려오는 바다"다.

### 4-3. 우리 구현 실측

```
GF = 0.425          포락선 최대/평균 = 2.31
```

**군은 있다. 다만 실제 바다의 절반 정도다.** 사용자가 "합쳐졌다 사라졌다 하는 게 있는 것
같은데" 라고 한 것은 — 그 현상이 **있긴 한데 약해서** 알아보기 어려웠다는 뜻이다.

## 5. ❌ 진짜 문제 — 바다가 자기를 반복한다

한 점의 수면 높이가 **몇 초 뒤에 자기와 얼마나 닮았는지**(자기상관)를 쟀다.
실제 바다는 몇 주기 안에 0 으로 떨어지고 **다시 안 올라온다.**

| 지연 | 1초 | 2초 | 3초 | 5초 | 8초 | 12초 | 20초 | 30초 | 45초 | **60초** | 90초 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 상관 | −0.49 | 0.09 | −0.16 | **0.43** | −0.24 | 0.06 | 0.22 | **0.39** | −0.29 | **0.33** | 0.01 |

**5초에 0.43, 30초에 0.39, 60초에 0.33.** 안 죽는다.

이게 "너무 일정한 파도"의 수학적 정체다. 정현파 10개의 합은 **준주기 함수**라, 성분이
적을수록 위상 관계가 금방 되돌아온다. 파장·위상을 아무리 불규칙하게 골라도
**개수가 적으면 반복은 안 없어진다.**

> **핵심** : 파도 공식이 틀린 게 아니다. 표본이 10개뿐이라 "바다"가 아니라
> "10음 화음"인 것이다.

## 6. 파형의 비선형 — 왜 마루가 뾰족한가

선형 이론의 파는 정현파라 마루와 골이 대칭이다. 실제는 **마루가 좁고 뾰족하며 골이 넓다.**

- **Stokes 파** : 2차 항을 더한다. `h = a·cos φ + ½k a²·cos 2φ`.
  우리 코드의 `b`(β, 2차 조화파)가 이 역할이다.
- **Gerstner(트로코이드) 파** : 물 입자가 원운동한다는 **엄밀해**. 정점을 마루 쪽으로
  **옆으로 밀어** 진폭을 안 올리고도 마루를 뾰족하게 만든다. 우리 `gerstner` 가 이것.
  ⚠ `Σ g·k·A ≤ 1` 을 넘으면 파가 스스로를 말아 올려 격자가 뒤집힌다.
  코드에 `gerstnerLoopLimit()` 로 들어가 있다 (지금 한계 0.727, 사용 0.38).
- **부서짐의 한계** : 가파름 `H/λ > 1/7` (마루 각 120°) 이면 부서진다.

우리는 이 셋을 다 갖고 있다. **이쪽은 손댈 게 없다.**

## 7. 컴퓨터 그래픽스의 세 갈래 — 무엇을 사고 무엇을 파는가

### ① 정현파의 합 (지금 우리)

```
h(x, t) = Σ Aᵢ · sin(kᵢ · (dᵢ·x) − ωᵢ t + φᵢ)
```

- **산다** : 해석적이다. 임의의 좌표에서 CPU 로 바로 계산된다 → **배의 부력**이 공짜.
  텍스처도, 리드백도, 프레임 지연도 없다. GPU/CPU 가 같은 식을 쓰므로 안 어긋난다.
- **판다** : 성분 수에 비용이 선형으로 든다. 적으면 반복이 보인다 (**지금 이 문제**).

### ② FFT 바다 (Tessendorf)

주파수 공간에서 스펙트럼대로 진폭을 깔고 무작위 위상을 준 뒤, 시간 발전을 `e^{iωt}` 로
주고 **역 FFT** 해서 높이장을 만든다. 업계 표준(영화·게임 대부분).

- **산다** : 성분이 256² = 65,536개다. 통계가 실제 바다와 맞고 반복이 눈에 안 띈다.
- **판다** : 결과가 **텍스처**다. 배의 부력을 위해 임의 좌표를 CPU 로 물으려면
  (a) GPU 리드백 — 동기 스톨, 우리가 `sim.sampler()` 에서 이미 겪은 문제, 또는
  (b) CPU 에서 FFT 를 한 번 더 — 코드가 두 벌이 된다.
  ⚠ **불변식 2 가 금지하는 바로 그 상황**이다 (GPU/CPU 가 갈라지면 배가 잠긴다).
  그리고 FFT 타일은 공간적으로 **반드시 반복**한다 (보통 타일을 크게 잡아 숨긴다).

> ⚠ **중요** : FFT 바다도 결국 **정현파의 합**이다. 방식이 다른 게 아니라 **개수가
> 65,536개**인 것이다. 우리와 종류가 다르지 않다.

### ③ 파동방정식 시뮬 (우리도 일부 쓴다)

`sim.js` 가 하는 것. 격자에서 `∂²h/∂t² = c²∇²h` 를 푼다.

- **산다** : 상호작용이 공짜다 — 배가 물을 밀면 항적이 생기고 퍼진다.
- **판다** : 격자 크기 안에서만 존재하고, 이 이산화는 **분산관계가 물리와 다르다**
  (모든 파가 같은 속도로 간다 — 심해 파의 성질이 아니다). 그래서 우리는 이걸
  **너울에는 안 쓰고 항적·교란에만** 쓰고 있다. 그 판단은 맞다.

## 8. ❌ 첫 가설은 틀렸다 — 대역 수는 지렛대가 아니었다

**처음 세운 가설** : *"부족한 것은 방식이 아니라 개수다. 10 → 40~64 로 늘리면 된다."*
**재 보니 아니었다.** 이 절은 그 기각 기록이다.

### 8-1. 비용 — 얼마나 드는가 (실측)

수면과 같은 정점 수(263,169)로 합성 벤치마크를 만들어, 대역 수만 바꿔 가며 쟀다.
H·G·D 를 전부 계산하는 같은 형태다. 3라운드 교차 측정 후 최솟값.

| 대역 | 0 | 10 | 16 | 24 | 32 | 48 | 64 | 96 |
|---|---|---|---|---|---|---|---|---|
| ms | 0.315 | 0.305 | 0.312 | 0.470 | 0.583 | 1.222 | 1.558 | 2.497 |
| 대역 몫 | — | ~0 | ~0 | +0.16 | **+0.27** | +0.91 | **+1.24** | +2.18 |

**16대역까지는 공짜다** (측정 잡음 아래 — 이 구간은 정점 ALU 가 병목이 아니다).
그 위로는 대역당 약 **19~23µs** 씩 는다.

⚠ 대역 수에 비례하는 비용은 **수면 정점 셰이더 하나뿐**이다. 확인 :
`swellH/G/D` 호출은 `water.js` · `grid.js` 의 **정점 셰이더에만** 있고, 시뮬의
`swellMain` 은 `slice(0, 4)` 로 **상위 4대역 고정**이라 N 과 무관하다.

### 8-2. 효과 — 얼마나 좋아지는가 (실측)

JONSWAP 스펙트럼에서 대역을 뽑아(로그 간격 · 시드 위상 · 방향 분산) 시드 3개 평균 :

| 대역 | 10 | 16 | 24 | 32 | 48 | 64 | 96 |
|---|---|---|---|---|---|---|---|
| 군집도 GF | 0.381 | 0.411 | 0.418 | 0.385 | 0.496 | 0.459 | 0.465 |
| 20초 이후 최대상관 | 0.868 | 0.715 | 0.647 | 0.599 | 0.518 | **0.467** | 0.582 |

**목표(GF 0.6~1.0 · 최대상관 0.15)에 어느 쪽도 도달하지 못한다.**
64대역에서 최대상관 0.47 — 목표의 3배다. 그리고 **96에서 오히려 나빠진다.**

다른 축도 전부 걸어 봤지만 (32대역 기준, 시드 3개 평균) :

| 조건 | GF | 20초+ 최대상관 |
|---|---|---|
| 기준 (γ3.3 · λ1.2~40 · 표류) | 0.458 | 0.633 |
| γ 1.0 (완전발달, 넓은 스펙트럼) | 0.459 | 0.586 |
| 파장 상한 80 | 0.433 | 0.658 |
| 파장 하한 0.6 | 0.386 | 0.634 |
| 방향폭 ±40도 | 0.452 | 0.662 |
| **배가 순항 (4.2/초)** | 0.244 | 0.601 |
| γ1.0 + 방향폭 + 순항 | 0.218 | 0.560 |

**아무것도 바늘을 못 움직인다.** 전부 0.56 ~ 0.66 안에 갇힌다.

### 8-3. 왜 안 되는가 — 유효 대역 수 (N_eff)

정현파 합의 자기상관은 `R(τ) = Σ (Aᵢ²/2)·cos(ωᵢτ)` 다. 이게 0 근처에 머물려면
**에너지를 나르는 성분이 충분히 많아야** 한다. 그 개수는 대역 수 N 이 아니라 :

```
N_eff = (Σ Aᵢ²)² / Σ Aᵢ⁴          (참여율, participation ratio)
```

스펙트럼이 뾰족하면 대부분의 에너지가 첨두 근처 몇 개에 몰려서, **대역을 아무리 늘려도
꼬리의 대역들은 에너지를 안 나른다.** 실측 :

| 구성 | 대역 수 | **N_eff** |
|---|---|---|
| 지금 (손으로 고른 10대역) | 10 | **6.3** |
| JONSWAP γ3.3 | 32 | 9.1 |
| JONSWAP γ3.3 | 64 | **18.5** |
| JONSWAP γ3.3 | 96 | 28.0 |
| JONSWAP γ3.3 | 256 | 75 |
| PM γ1.0 (더 넓은 스펙트럼) | 64 | 26.6 |
| PM γ1.0 | 256 | 108 |
| **FFT 바다 (Tessendorf 256²)** | 65,536 | **수천** |

**64대역을 써도 실효 성분이 6.3 → 18.5 로 세 배 늘 뿐이다.** 비용은 +1.24ms(물 전체의
29%)를 내고 반복은 0.87 → 0.47 로만 준다. **값을 안 한다.**

> **정리** : "정현파를 몇 개 더 얹으면 된다" 는 틀렸다. 반복을 없애려면 N_eff 가 수백~수천
> 이어야 하고, 그건 정현파를 손으로 세는 방식으로는 도달할 수 없는 자리다.
> FFT 바다가 반복이 안 보이는 이유가 **바로 이것**이고, "성분이 많다"는 그 차이가
> 양이 아니라 **질적 차이**다.

### 8-4. 그래서 다음은

**⚠ 아직 정할 수 없다.** 위 실측은 "무엇이 답이 아닌지" 만 알려 줬다. 남은 갈래 :

- **(가) 32대역으로 소폭.** 비용 +0.27ms 로 거의 공짜고, 손으로 고르는 대신 스펙트럼에서
  뽑으니 원리적으로 깔끔해진다. 다만 **반복은 여전히 보일 것이다** (N_eff 9).
  "이왕 만질 거면" 수준의 개선이지 문제의 해결이 아니다.
- **(나) FFT 로 간다.** 반복은 확실히 사라진다. 대가는 배의 부력 — 임의 좌표의 수면
  높이를 CPU 로 물어야 하는데 결과가 텍스처가 된다. 불변식 2 가 금지하는 상황이고
  이 프로젝트에서 가장 자주 깨진 자리다. **가능한 우회**는 "부력만 지금의 해석적
  10대역으로 계속 풀고, 화면만 FFT" 인데 — 그러면 **배가 보이는 파도와 다른 파도를
  탄다.** 이게 허용되는지가 결정 사항이다.
- **(다) 문제를 다시 정의한다.** 아래 8-5.

### 8-5. ⚠ "일정하다" 의 정체를 다시 물어야 한다

내가 세운 지표(시간 자기상관)가 **눈이 보는 것과 다를 수 있다.** 근거 :

- 어떤 조건에서도 0.56 아래로 안 내려가는데, 그 안에서도 화면은 꽤 달라 보인다
  (긴 너울을 넣었을 때가 그랬다 — 지표는 거의 안 변했는데 화면은 눈에 띄게 나아졌다).
- 사람은 60초 전의 수면 높이를 기억하지 않는다. **한 화면 안의 공간적 다양성**을 본다.

**레퍼런스 사진과 우리 화면의 가장 큰 차이는 사실 시간이 아니라 잔결이다.**
사진의 바다는 표면 전체가 잔물결·거품·질감으로 덮여 있다. 우리는 매끈하다.
기하로는 못 넣는다 — 정점 간격이 0.215(110/512)라 파장 1.0 밑은 그릴 수 없다.
**그건 노멀·셰이딩의 몫이다** (`microA/microB` 가 이미 그 자리에 있다).

→ **다음에 잴 것** : 시간 자기상관 말고 **한 화면 안의 공간 통계**.
   (예 : 화면 밝기의 국소 분산, 기울기 분포의 첨도, 특징 스케일의 개수)
   그리고 잔결을 노멀에 넣었을 때 그 지표가 움직이는지.
