## 세 단계로 진행됐다

### 1단계 — 컨셉과 기본 구조 (~08-30)

흰 여백 위를 종이배 한 척이 떠간다. 하늘도 지평선도 없고, 물은 배경색(`#F8F7F3`)으로 흩어져 사라진다.

- **바다** = 향의 지도. 좌표는 있지만 경계는 없다.
- **배** = 사용자의 시점. 카메라는 월드에 고정이고 도는 것은 배뿐이다.
- **항적** = 지나온 취향의 기록.

수면을 노이즈가 아니라 **실제 파동방정식**으로 풀기로 결정한 것이 이 단계의 핵심이다.
640² half-float 핑퐁 렌더타깃, 고정 타임스텝 1/120초, 전파 계수 0.34, 감쇠 0.9975.
가장자리 흡수층으로 벽 반사를 없애고, 배가 나아간 만큼 높이맵을 밀어(이류) 물이 배를 지나 흘러가게 했다.
선체는 파를 더하지 않고 흘수만큼 **붙잡는다** — 누적 발산이 없고 항적이 자연히 남는다.

등고선 그리드는 처음 2단 LOD였다가 링 경계가 눈에 보여서 **3단으로 다시 짰다**.
셀 크기를 정확히 2배씩(0.4 / 0.8 / 1.6) 두어 굵은 선의 격자가 항상 겹치고, 페이드 구간을 넓게 잡고
알파에 `sqrt` 보정을 걸어 겹침 구간에서 선이 묽어지지 않게 했다.

향 영역 4개(FLORAL / WOODY / FRESH / SWEET)를 좌표에 배치하고, 검색어가 키워드에 맞으면
배가 스스로 뱃머리를 돌리게 했다. 영역은 100 단위로 순환한다 — 어느 방향으로 돌아도 다시 나타난다.

### 2단계 — 파면 교란과 빛 (08-30 ~ 08-31)

물의 성격을 바꾼 단계다. 자세한 경위는 `파면 작업 보고.md`.

- **점 교란 → 선(파면) 교란.** 법선 방향은 가우시안, 파면 방향은 4제곱 — 가운데가 평평하고 끝만
  떨어져 선으로 읽힌다. 가우시안이면 양 끝이 뾰족해져 다시 점이 된다.
- **발생 간격 0.025초 → 0.40초.** 잦은 잡티가 아니라 드물게 큰 것 하나.
- **바다에 주방향을 줬다.** `seaDir` 이 0.02 rad/s 로 천천히 돌고 파면은 그 ±25도 안쪽에서 난다.
  다만 전부 나란하면 서로 지나가지 않아 간섭이 없다 — 일부(`crossMix 0.35`)를 교차 방향으로 뺐다.
- **잔물결 대역 추가.** GPU `swellH` 와 CPU `swellCPU` 양쪽에 같은 항을 넣어 배가 잠기지 않게 했다.
- **선의 명암·분광·반짝임을 새로 구현.** 골은 먹 쪽, 마루는 배경 쪽(`lineContrast`).
  경사면이 향한 방향에 따라 색이 옅게 갈리고(`iriAmount`), 마루에서 선이 끊기며 튄다(`glintAmount`).

이 단계에서 **지시와 다르게 한 것이 하나 있다.** 파면 발생 거리를 uv 0.34~0.46 대신 0.22~0.28 로 좁혔다.
흡수층이 uv 0.29 부터 진폭을 깎기 때문에, 지시한 거리에 낳으면 태어나는 순간 먹힌다.
방향과 "한쪽에서 밀려온다"는 성질은 남았지만 조주 거리가 짧아졌다.
더 멀리서 밀려오게 하려면 스펀지 시작점을 0.58 → 0.72 로 밀고 `ambEdge` 를 0.34 로 올려야 한다.

작업 중 버그 하나를 잡았다. `atan(y, x)` 는 두 인자가 0이면 GLSL ES 에서 미정의이고,
정지한 원경은 `vGrad` 가 정확히 (0,0) 이다. NaN 이 격자 전체를 오염시킬 수 있어 `+1e-6` 가드를 넣었다.

### 3단계 — 로컬 프로젝트로 이식 (08-31, 방금)

클로드 코드에서 이어가기 위해 단일 파일을 `paperboat/` 로 옮겼다. **물리·셰이더·수치는 그대로다.**

- 컴포넌트 런타임 의존 제거. 순수 three.js + ES 모듈, Vite.
- 기능별 11개 모듈로 분리 : `config / params / sim / water / grid / spray / boat / zones / input / ui / swell`.
  렌더 루프와 항해 상태만 `main.js` 에 남았다.
- `this.props.x ?? CONFIG.y` 패턴을 `params.js` 로 합쳤다. Tweaks 25개 값이 그대로 대응하고,
  콘솔에서 `PB.params.x = …; PB.apply()` 로 만질 수 있다.
- three.js 를 npm 의존(0.160.1 고정)으로 바꿨다.
- 인계 문서 3종 : `README.md`(구조·시간 규칙·수정 지점·함정), `CLAUDE.md`(불변식 8개·금지 항목),
  `TODO.md`(고도화 항목별 진입점).
- 이식 직후 입력 바인딩 버그를 잡았다. 입력을 `#stage` 에 붙여 검색창 드래그가 조타로 새고 있었다
  → 캔버스 영역(`#mount`)으로 옮겼다.

### 4단계 — 성능 바닥과 안전망 (09-01)

`docs/작업계획.md` [1단계]를 코드로 닫았다. **아트는 아직 손대지 않았다 — 그림은 그대로다.**

- `src/perf.js` 신설. 개발 빌드 전용 계측 HUD (GPU 시간 · 드로우콜 · 게이트 간격 · LoAF).
  stats-gl 을 안 쓴 이유와 함정은 작업계획 [1단계]에 적어 뒀다.
- 기준선 재측정 결과가 08-31 실측과 **완전히 일치**했다 — 드로우콜 13 / 삼각형 131,126 / 선분 64,720.
- `uCam` x=0 하드코딩 제거. 런타임 값이 `[0, 8]` 로 기존과 동일해 그림이 안 변한다.
  **이제 카메라를 움직일 수 있다** (Top View · 도착 샷의 전제 조건이었다).
- `visibilitychange` + `t` 자체 누적, `onResize` 리스트 + rAF 디바운스, 전 모듈 `dispose()`.
- 지뢰 둘 처리 : `sim.sampler()` 를 배 게이트 안으로, `setClearColor` 복원.
- 죽은 CONFIG 키 14개 삭제 (전부 참조 0 확인 후).

**아래 ⚠ 표의 다섯 항목 중 "30초 누적 발산"은 이 단계에서 코드로 확인됐다.** 60 시뮬초를 돌려
월드 최대 파고가 10초 값보다 오히려 낮았고(0.169 → 0.148), NaN/Inf 텍셀이 0이었다.
나머지 네 개(파면 결·방향·밀려옴·정지 시 뚜렷함)는 여전히 **사람이 봐야 한다.**

**성능 예산도 실사용 창에서 재서 전 항목 통과했다** (71초·8,518프레임, Intel Arc iGPU · 120Hz).
rAF p95 13.5ms / LoAF 워밍업 이후 0ms / 게이트 83.4·124.4ms / 드로우콜 13. 자세한 것은
작업계획 6-2e. 여기서 **시뮬 스텝 버스트가 정량화됐다** — GPU 시간이 평시 3.66ms 인데 최대
12.85ms 로 튀고, p95 를 끌어올리는 것이 등고선이 아니라 이 버스트라는 게 확인됐다.

측정치를 눈으로 못 읽는 환경을 위해 `?perf` → `/__perf` → `perf-report.json` 회수 경로를
같이 만들었다 (개발 서버 전용, gitignore).

### 5단계 — 아트 디렉션 (09-01)

`docs/작업계획.md` [2단계]. 빛·반사·일렁임·융기를 한 번에 확정했다. 자세한 경위와 실측은 그 장에.

- **빛** — `main.js` 의 `dirLight`(그동안 배 전용이던)를 그리드·물보라가 같이 본다.
  **배와 물이 처음으로 같은 곳에서 빛을 받는다.**
- **반사** — 진짜로 넣지 않았다. "그늘진 면에서 등고선이 짙어지는 국소 변화"로 재정의.
- **일렁임** — 잔물결 대역 하나 추가. 기존 대역과 가까운 주파수로 맥놀이를 만들었다.
- **융기** — Gerstner 횡변위. 등고선이 마루에 몰려 융기로 읽힌다. 진폭은 하나도 안 올렸다.
- `swell.js` 를 `BANDS` 표 하나에서 GLSL·CPU 를 생성하도록 고쳤다.

**작업 중 계획과 갈라진 지점이 셋 있었고, 셋 다 실측이 알려줬다.**

1. 계획의 물리적 `dot(N, L)` 레시피가 이 씬에서 작동하지 않았다 — 바다가 월드 단위로 거의
   평평해서(기울기 중앙값 0.036) 내적이 0.61~0.69 에서만 움직인다. 경사의 방향과 세기를 갈랐다.
2. 빛을 높이 명암과 같은 `clamp` 안에 더하면 잘린다 (높이 항만으로 이미 포화 상태).
3. **흰 종이 위에서는 빛이 아니라 그늘을 그려야 한다.** 대칭으로 변조했더니 원본보다 그림이
   흐려졌다 — 여기서 "밝게"는 곧 "선 지우기"다. 단방향으로 바꾸니 파면이 띠로 읽히기 시작했다.

검증 : 광원 180도 뒤집기에 잉크 픽셀의 60% 가 반응 / GLSL·CPU 대조 3,996 표본 최대오차 0 /
Gerstner 역변환 오차 0.00072(없으면 0.02) / 배 40초 안정 / NaN 0 /
**GPU 비용은 네 조합 전부 1.72~1.83ms 로 측정 노이즈 안** / 번들 gzip 140.82KB.

### 6단계 — 표현면을 그리드에서 수면으로 (09-01, 사용자 지시)

5단계를 끝낸 뒤 사용자가 **"격자 배열을 삭제해야 할 것 같다, 빛 반사가 진행되는지 모르겠다"** 고
지적했고, 재보니 정확했다. **그리드가 화면 잉크의 86.2% 를 차지**하고 있었고 수면 메시는
배경색으로만 칠했다 — 즉 그리드는 배경 요소가 아니라 유일한 표현면이었고, 빛·반사가 전부
그 선 위에서만 일어나 격자에 덮여 있었다.

- **`water.js` 가 자기 명암을 갖는다.** 배경(밝기 246)보다 밝을 수 없으므로 물을 조금 내려놓고,
  빛을 받는 면이 배경색으로 올라오는 것을 하이라이트로 삼았다.
- **`showGrid` 기본 꺼짐.** GPU 1.904 → 1.177ms (38% 감소), 선분 64,720 → 0.
- **오로라 분광** 추가. 프레넬 × 경사의 좁은 구간(리본) × 빛을 향한 면으로 삼중 필터.
  ⚠ 필터 없이 넣었더니 무지개가 화면 100% 를 덮어 기름막이 됐다.
- **파도의 규칙성**을 깼다 (대역 4 → 7). 그리드를 끈 덕에 파장 2.8 까지 잘게 넣을 수 있게 됐다.
- **거리 LOD.** 잔물결 대역과 오로라만 거리에 따라 끈다. GPU 0.139 → 0.107ms (23% 감소).

⚠ 5단계에서 넣은 버그를 하나 잡았다 — `vGradW` 의 시뮬/너울 z 부호 불일치. 세 모듈 다 고쳤다.

## 다음

사용자가 정한 방향은 **모든 기능·디자인 고도화** — 빛, 파도, 일렁임, 반사, 향수 클릭 오브젝트.
항목별 진입점과 주의사항은 `paperboat/TODO.md` 에 있다. 요약하면:

- **빛** — 분광과 반짝임은 있지만 광원 개념이 없다. 방향광 하나를 정의해 둘을 묶으면 방향감이 생긴다.
- **파도** — 융기가 선의 짙어짐으로 읽힌다. 융기 자체를 보려면 `sim.height` 를 올린다(발산 감시 필요).
- **일렁임** — 잔물결 대역을 더 얹는 것이 가장 값싼 개선. GLSL·CPU 양쪽에.
- **반사** — ⚠️ 지금 수면은 조명이 닿지 않는다. 하늘도 지평선도 없는 흰 여백에서 무엇을 비출지
  먼저 정해야 하는, 그림 전체의 전제를 다시 잡는 작업이다.
- **향수 클릭 오브젝트** — 클릭 대상 자체가 없다. 메시 + Raycaster + 클릭/드래그 구분이 필요하다.

그리고 기획 단계부터 남아 있는 가장 큰 구멍은 그대로다 — **도착 상태가 없다.**
영역에 들어가도 물 색만 변하고 다음 행동으로 이어지지 않는다. 향수 클릭 오브젝트와 같이 설계하는 것이 자연스럽다.

**깃허브 푸시는 로컬에서 해야 한다.** zip 을 `custompjt/paperboat/` 로 넣고 커밋한다.
