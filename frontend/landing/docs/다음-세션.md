### ⭐ 떨림은 **스크린샷을 번갈아 찍어** 잡는다 (09-10)

스크린샷 한 장이 rAF 를 **한 프레임** 돌린다. 마우스를 한 자리에 고정하고 스크린샷과 측정을
번갈아 하면 프레임 사이의 움직임이 숫자로 나온다. ⚠ 재는 것은 **화면 좌표**여야 한다 —
월드 좌표는 배가 표류하면 당연히 변해서 판정이 안 된다.

```js
const v = mesh.position.clone().project(cam);

```

그건 시차가 아니라 **팬**이라 월드에 고정된 층이 통째로 밀린다. 시차는 평행이동만으로 난다.

### rAF 펌프 (창이 숨겨져도 재는 법)

```js
// ⚠ 설치 → 스크린샷 → cbs.length ≥ 1 확인 → 그다음 펌프.
//   같은 호출에서 펌프하면 큐가 비어 있어 t≈0 인 얼어붙은 씬을 잰다 (실제로 오진했다)
// ⚠ 원본을 먼저 보관한다 — 끝나면 아래 '되돌리기' 로 반드시 원복한다
window.__real = { raf: window.requestAnimationFrame.bind(window), caf: window.cancelAnimationFrame.bind(window) };
const cbs=[]; window.__cbs=cbs;
window.requestAnimationFrame=cb=>{cbs.push(cb);return cbs.length;};
window.cancelAnimationFrame=()=>{};
let t=performance.now();
window.__pump=(n=1,dt=33.3)=>{for(let i=0;i<n;i++){const q=cbs.splice(0);t+=dt;for(const c of q)c(t);}return cbs.length;};
```

⚠ **A/B 사이에 펌프하지 않는다.** 유니폼만 바꾸고 다시 그린다.
⚠ 펌프는 매 틱 PARAMS 에서 유니폼을 덮어쓴다 — 펌프를 끼우려면 `PARAMS` 를 바꿔야 한다.
⚠ **GPU ms 를 이 창에서 인용하지 않는다.** 숨겨진 패널에서는 수면 셰이더를 통째로 꺼도
1.81ms 로 고정이었다. 비용은 `debugView 12`(픽셀당 해시 수)로 잰다.
⚠ 한 호출에 1,200프레임을 돌리면 `javascript_tool` 이 시간 초과로 죽는다 (*Internal error*). 150프레임 안팎으로 나눈다.

### ⭐ 시계 합성 — **초**를 재려면 (09-11)

펌프가 콜백에 넘기는 시각을 **앱은 안 읽는다.** 앱은 `THREE.Clock` → `performance.now` 로 dt 를 잰다.
그래서 펌프 횟수 × 33.3ms 는 앱 시간이 아니다 — 첫 측정의 *"lead 2.1초"* 가 그 착시였다 (실제 1.2초).
타임라인 · 트윈 길이 · `hold` 처럼 **초**를 재는 검사는 시계까지 합성한다.

```js
// 위 rAF 펌프를 설치한 뒤에. THREE.Clock 이 이 값을 읽는다
window.__realNow = window.__realNow || performance.now.bind(performance);
let fake = window.__realNow();
performance.now = () => fake;
window.__pumpT = (n = 1, dt = 33.3) => { for (let i = 0; i < n; i++) { fake += dt; const q = __cbs.splice(0); for (const c of q) c(fake); } };

// 되돌리기 (펌프와 시계를 같이)
performance.now = window.__realNow;
window.requestAnimationFrame = window.__real.raf; window.cancelAnimationFrame = window.__real.caf;
__cbs.splice(0).forEach(cb => window.__real.raf(cb));
```

⚠ `tick()` 이 dt 를 **0.05초로 자른다** — 증분을 50ms 넘게 주면 앱 시간이 덜 간다.

### ⭐ 창 크기를 바꾸면 **렌더러부터** 찍는다 (09-11)

- **`colorWrite` 차이 마스크에 투명 층이 섞였다** (선체 톤). 선체 **앞**의 물보라·부표는 뒤에 무엇이 있느냐에 따라 섞이므로 선체를 끄면
  값이 바뀌어 마스크에 들어온다. 같은 설정이 두 번 다른 값을 냈고, 300° 는 톤을 바꿔도 `87.1% · 1.256` 그대로였다.
  **배 밖 투명 층을 숨기고** 다시 재니 단조로워졌다 — ⑨ 의 *"끈 것/켠 것으로 잰다"* 가 **마스크 자체**에도 적용된다
- **`resize_window` 뒤의 스크린샷은 믿지 않는다.** 좌상단 4분의 1 만 잘려 오거나(배율 1) 흰 화면이 오고, 새로 불러오기 전까지 안 풀린다.

- **스크린샷이 한 장 늦게 온다** — 방금 바꾼 것이 안 보이면 한 장 더 찍는다 (3번 겪었다. 오버레이를 치웠는데 오버레이가 찍혔다)
- **펌프 부트스트랩 스크린샷의 '시간 초과' 는 무해하다** — 큐에 tick 이 들어와 있으면(`__cbs.length ≥ 1`) 성공이다.
  rAF 를 가로챘으니 도구가 기다리는 다음 프레임이 안 오는 것뿐이다
- **반사 타깃은 배 게이트(30fps)에서만 다시 찍힌다** — 값을 바꾼 첫 프레임에는 옛 반사가 남아 있다. `titleReflect` 를 0.35 로 바꾸고
  "안 먹는다" 로 읽을 뻔했다. 두 장 찍는다
- ⭐ **진짜 픽셀을 크게 보는 법** — 같은 태스크에서 `PB.bloom.render(scene, cam)` → `canvas.toDataURL()` → 고정 오버레이 캔버스에

## 7. ⭐ 축척 — 인용할 때 여기서 가져온다 (v0.15.7 실측, 2026-09-07)

```
ℓ = 1 / (0.62 · waveSpeed)²  [m/월드]      ← BANDS 의 0.62 는 배율이 아니라 길이 단위다
waveSpeed 1.00  →  1 월드 = 2.601 m
  배 13.01 m (5 월드) · 주파장 20.81 m (8.0 월드) · 유의파고 2.49 m · 주기 3.65 s
무차원 (ℓ 과 무관 — 이걸로 판정한다)
  선체속도/cp 0.7909 · v/cp 순항 0.384 · 부스트 0.780 · 가파름 0.120 · 궤도 kσ 0.188
  파장 ÷ 배 길이 1.60 척 · rms 기울기 0.144(8.2도) · Gerstner 종횡비 0.45 : 1
```

⚠ **`waveSpeed` 는 속도가 아니라 축척이다.** 내리면 파도가 느려지는 게 아니라 **바다가 커진다**.

⚠⚠ **여기 숫자를 손으로 옮겨 적지 말고 `PB.clock.report()` 를 찍어라.** 이 블록은
2026-09-07 이전까지 **v0.12.0 값이 그대로 남아 "그대로 유효" 라고 적혀 있었다** — v0.12.2 가
배를 2.48 → 5.0 으로, v0.12.3 이 주파장을 3.2 → 8.0 으로 바꾸면서 여덟 값 중 **여섯이 틀렸는데도**
세 세션을 살아남았다 (배 6.45→13.01m · 주파장 8.32→20.81m · 주기 2.31→3.65s ·
선체속도/cp 0.8807→0.7909 · v/cp 0.429→0.384 · 가파름 0.282→0.120 · 궤도 kσ 0.443→0.188).
`report()` 는 전부 `BANDS` 와 `CONFIG` 에서 파생시키므로 조용히 낡을 수가 없다.

### 향수 지도의 축척 (09-11) — **`PB.scentMap.report()` 를 찍는다**

지도 320 × 266 월드 = **832 × 691 m** · 부스트 횡단 **3.1분** · 배 속도 순항 0.84 · 자동 조타 1.27 · 부스트 1.71 월드/초.
⚠ `scentMapReport()` 는 `metersPerWorld()` · `groundSpeed()` 에서 파생한다 (처음에 2.601 을 손으로 적었다가 고쳤다) —
위 블록과 같은 이유로 여기 숫자도 옮기지 말고 찍는다.

### 선체속도/cp 는 **`√(L / λp)`** 다 — 외우지 말고 이 식을 쓴다

`HULL_K` 1.25 가 `√(g/2π)` = 1.2495 라서 상수가 1 로 떨어진다 (실측과 오차 0.04%).

| L (월드) | λp (월드) | √(L/λp) | 언제 |
|---:|---:|---:|---|
| 2.48 | 3.2 | 0.8803 | v0.12.0 이전 |
| 5.0 | 3.2 | 1.2500 | v0.12.2 (배만 키운 구간) |
| **5.0** | **8.0** | **0.7906** | **지금** |

⚠ 그래서 **`lengthW` 든 `BANDS` 든 한쪽만 바꾸면 이 비가 움직인다.** `v/cp > 1` 은 배가 자기
앞 파도를 앞지르는 화면이라 어떤 축척에서도 물리적으로 존재하지 않는다 — v0.12.2 의 1.25 가
바로 그 상태였고, v0.12.3 이 파장을 늘려 0.79 로 내렸다.

### 반직관적이라 두 번 이상 속은 것

- **속도를 줄이면 각속도도 줄인다.** 보존할 것은 ω 가 아니라 **선회 반경** v/ω
- **`foamDecay` 는 초로 정하지 않는다.** 지킬 것은 *반감기 동안 마루가 앞서는 파장 수*(0.40λ)
- **`foamBlur` 를 내리면 거품이 길어진다.** 5탭은 확산이 아니라 **감쇠기**다
- **`vite build` 통과 ≠ GLSL 컴파일 성공.** 판정은 `renderer.info.programs` 와 `gl.getError()`
- **GLSL 주석 안의 백틱이 빌드를 죽인다** (셰이더가 JS 템플릿 리터럴이다). 오늘도 한 번 죽었다
- **`hash2` 는 [0,1] 이 아니라 [−0.5, +0.5]** 를 돌려준다
- **게이트를 곱으로 쌓지 않는다** — 셋이면 화면 최대차가 몇 레벨로 죽는다
- **`dirf` 는 준-이진이다** — 면적의 69.5% 가 `|dirf| > 0.9`
