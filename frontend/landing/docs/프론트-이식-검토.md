## 3. 백엔드 — `origin/develop` (2026-09-14 fetch)

- **V6** `align_scent_map_schema_with_delivered_data` — `perfumes.fragrantica_id` (UNIQUE) · 계열 9코드 (CITRUS · FRUITY · FLORAL · GREEN · AQUATIC · WOODY · AMBER · GOURMAND · MUSK, `display_order`) ·
  `scent_regions.polygon` (JSONB) + anchor · 좌표 CHECK 0~1 · `perfume_neighbors.similarity` (+ V5 의 `rank`)
- 적재 `backend/db/seed/load_scent_map.sql` + CSV 6개 — **좌표 · 이웃이 paperboat 데이터와 200/200 같다** (같은 원본 `scent_map.json` 에서 나왔다)
- API
  - `GET /api/v1/map` → `{ regions: [{ scentRegionId, code, name, displayOrder, anchorX, anchorY, polygon }], perfumes: [{ perfumeId, name, imageUrl, x, y, scentRegionId }] }` — 배 가까운 향수는 화면이 직접 고른다 (컨트롤러 주석)
  - `GET /api/v1/map/perfumes/{id}` → 지도용 요약 (nameKo · imageUrl · x · y · scentRegionId)
  - `PUT · GET /api/v1/map/exploration/me` · `GET /api/v1/map/exploration-logs` — 향해 일지. 구역 진입은 계열 **폴리곤**으로 판정한다 → 엔진은 월드 좌표가 아니라 **지도 좌표(0~1)** 로 보낸다 · 빈 바다 이동도 기록된다 (V9)
  - `GET /api/v1/perfumes/{id}/neighbors` · `/similar` — 둘 다 `perfume_neighbors` 를 rank 순으로 읽는다 (거리 계산 없음)
- 지도 배경(땅 · 바다 · 해안선 128×108 격자)은 API 에 없고 정적 파일로 내려주기로 했다 (V6 주석)
- 호스트 develop 프론트의 `features/map/api.ts` 는 아직 자리표시자다

## 5. 검토에서 틀렸던 것 — 같은 함정

- 첫 검토는 호스트 **작업 트리**(design 브랜치 · develop 보다 107커밋 뒤)의 백엔드를 읽고 *"외부 id 컬럼 없음 · 구역 사각형 · 계열 시드 없음 · 일지 API 없음"* 이라고 적었다 — 전부 develop 에는 있었다.
  **`git fetch` 후 `origin/develop` 을 `git show` · `git grep` 으로 읽는다**
- 호스트 작업 트리에는 커밋 안 된 변경이 있다 — 브랜치를 바꾸거나 pull 하지 않는다 (읽기만)
- 유사도는 같은 날 한 번 뒤집혔다 — *"거리 유사도가 맞다"* → 백엔드 검사 뒤 *"백엔드 자료가 더 좋을듯"* 으로 확정. `scent_map.json` 의 `notes.neighbors` 문구는 데이터 팀 원본이라 손으로 고치지 않는다 (불변식 29-3)

## 7. 카드 동작 세 가지 — 호스트 경계 (v0.68.0 · 2026-09-15)
