다른 도구·모델에 이 문제를 물어볼 때 이 문서 하나만 주면 된다. 저장소 없이도 자립적으로 읽힌다.

## 0. 무엇을 만들고 있나

흰 종이 같은 여백 위를 종이배 한 척이 떠가는 three.js 랜딩. 향수 추천 서비스의 첫 화면이고,
바다는 "향의 지도"다. 목표 이미지는 **따뜻한 아이보리 배경 위에 차가운 진주빛 수면**,
파도 능선에만 옅은 보라·아이스블루 오로라, 최상단에 따뜻한 백색.

- three.js **0.160.1** (npm 고정), Vite 5, 순수 ES 모듈. React 없음.
- WebGL2. 후처리 없음(블룸 없음). `ShaderMaterial` 직접 작성.
- 렌더러 : `{ antialias: true }`, `setPixelRatio(min(dpr, 2))`, `outputColorSpace` 기본(sRGB).
  각 프래그먼트 끝에 `#include <colorspace_fragment>`.

## 2. 씬 구성

```js
const cam = new THREE.PerspectiveCamera(45, aspect, 0.1, 400);
// 매 프레임 : 속도 s(0..1) 에 따라 후퇴·상승·화각 확대
cam.position.set(0, lerp(2.8, 4.2, s), lerp(8.0, 12.5, s));
cam.fov = lerp(45, 58, s);
cam.lookAt(0, 0.35, -0.6);

scene.background = new THREE.Color('#F6F5F2');
// 이 두 조명은 종이배 전용이다. 수면은 조명을 안 받고 셰이더가 직접 색을 만든다
scene.add(new THREE.HemisphereLight(0xffffff, 0xe9e5d9, 1.35));
const dirLight = new THREE.DirectionalLight(0xffffff, 2.2);
dirLight.position.set(-5, 5, 3.5);
// 그 방향을 수면 셰이더에도 넘겨 배와 물이 같은 빛을 받게 한다
water.setLight(dirLight.position.clone().normalize());
```

**카메라는 월드에 고정이다.** 항해는 카메라가 움직이는 게 아니라 **물을 뒤로 흘려보내는 것**
(이류)으로 표현한다. 배는 항상 화면 가운데.

수면 메시 : `PlaneGeometry(110, 110, 256, 256)` 를 `rotation.x = -PI/2` 로 눕힘.
→ **월드 0.43 간격**. 이게 표현 가능한 최소 파장을 결정한다 (약 1.7).

## 3. 파도의 스펙트럼 (여기가 이 그림의 핵심)

`swell.js` 의 `BANDS` 표 하나에서 GLSL(`swellH`/`swellG`/`swellD`)과
CPU 사본(`swellCPU`, 배의 부력용)을 **문자열 생성으로 함께 만든다.** 둘이 갈라질 수 없다.

| 그룹 | 방향 (단위벡터) | k (파수) | ω | 상대진폭 | 파장 |
|---|---|---|---|---|---|
| swell | (0.860, 0.510) | 0.5712 | 1.4676 | 0.75 | 11.0 |
| swell | (−0.419, 0.908) | 0.8378 | 1.7774 | 1.00 | **7.5 ← 주파** |
| swell | (0.980, −0.200) | 1.2083 | 2.1347 | 0.62 | 5.2 |
| ripple | (0.360, −0.930) | 1.7453 | 2.5654 | 1.00 | 3.6 |
| ripple | (0.790, 0.610) | 2.3271 | 2.9624 | 0.62 | 2.7 |
| ripple | (−0.620, −0.780) | 2.9920 | 3.3590 | 0.38 | 2.1 |
| ripple | (0.140, 0.990) | 3.6960 | 3.7333 | 0.22 | 1.7 |

- 높이 : `h(p) = Σ Aᵢ·sin(dot(p,dᵢ)·kᵢ − ωᵢ·speed·t)`
  `A = (swell? oceanSwell : ripple) × 상대진폭`
- ω 는 심해 중력파 분산관계 **ω = 0.62·√(g·k)** (g=9.81) 에서 뽑았다.
  긴 파가 빠르고 짧은 파가 느려야 파들이 서로 미끄러지지 않는다.
- `detail` 인자로 **ripple 그룹만** 거리에 따라 끈다 (swell 은 지평선까지 유지).
- **Gerstner 횡변위** : `D(p) = g·Σ Aᵢ·cos(phaseᵢ)·dᵢ`. 정점을 마루 쪽으로 몰아 마루를 뾰족하게.

현재 값 : `oceanSwell 0.45`, `ripple 0.035`, `waveSpeed 0.55`, `gerstner 0.65`

여기서 나오는 실측치 —
**유의파고 2σ = 0.89**, **가파름(파고÷주파장) = 11.9%**, **기울기 중앙값 0.351**,
**배 길이 2.48 → 파도 하나에 배 3척.**

## 4. 수면 프래그먼트 셰이더의 구조

색을 만드는 순서다. 각 단계가 **직전 결과 위에 얹힌다.**

```glsl
// [입력] vGradW = 월드 기울기 (시뮬 + 너울), vW = 월드 위치, vDetail = 거리 LOD 계수
float slope = length(vGradW);
float steep = clamp(slope * uSteepK, 0.0, 1.0);              // uSteepK = 5.0
float lit   = -dot(vGradW/slope, uLightXZ) * steep;          // -1 등짐 ~ +1 받음

// 정규화된 파도 높이. 색의 모든 배치가 이 값 위에 선다
float h = clamp(0.5 + vW.y * uHNorm, 0.0, 1.0);              // uHNorm = 0.5 / 2σ
float crestMask = smoothstep(0.68, 0.94, h);
float apexMask  = smoothstep(0.95, 1.00, h);

// ① 기본색 : 골 → 중간 → 기본. 셋 다 차가운 쪽.
//    방향광은 별도 색 축을 만들지 않고 '높이를 미는' 것으로만 작용한다
float hc = clamp(h + uShade * lit * 0.16, 0.0, 1.0);         // uShade = 2.2
vec3 c = mix(uTrough, uMid, smoothstep(0.00, 0.55, hc));
c = mix(c, uBase,          smoothstep(0.45, 1.00, hc));

// ② 투과 : 법선을 8배 과장해야 스침각이 파도를 따라 변한다
vec3 N = normalize(vec3(-vGradW.x*8.0, 1.0, -vGradW.y*8.0));
vec3 V = normalize(cameraPosition - vW);
float fres = pow(1.0 - clamp(dot(N,V),0.0,1.0), 3.0);
c = mix(c, uTrans, fres * 0.22 * uSpec);

// ③ 수영장 바닥 : 시선 레이를 y = -uDepth 평면까지 내려 교점에서 격자를 샘플
vec3 I = -V;
float tHit = (vW.y + uDepth) / max(-I.y, 1e-3);              // uDepth = 5.0
vec2  fp   = vW.xz + I.xz * tHit + vGradW * uRefract;        // uRefract = 0.5 (굴절)
vec2  tg   = abs(fract(fp * uFloorK) - 0.5);                 // uFloorK = 1.35 → 칸 0.74
float dl   = 0.5 - max(tg.x, tg.y);
float fl   = 1.0 - smoothstep(0.0, uFloorW, dl);             // uFloorW = 0.025 (얇은 선)
float look = smoothstep(0.03, 0.40, V.y);                    // 내려다볼 때만 보인다
c = mix(c, uFloorLine, fl * uFloorAmt * (1.0-crestMask) * look * vDetail);

// ④ 능선 오로라 + 최상단 백색
float flow = 0.5 + 0.5*sin(vW.x*1.4 + vW.z*0.7 + uTime*0.18);
c = mix(c, mix(uViolet, uBlue, flow), crestMask * 0.25 * uIriAmt * vDetail);
c = mix(c, uApex,                     apexMask  * 0.90 * uIriAmt * vDetail);

// ⑤ 거리·가장자리 페이드로 배경색에 녹인다
gl_FragColor = vec4(mix(uBg, c, vis), 1.0);
```

| 역할 | 색 | 온도 |
|---|---|---|
| 배경·안개 | `#F6F5F2` | **따뜻함은 여기에만** |
| 수면 기본 | `#F0EFEC` | 거의 무채색 |

| 투과광 | `#EAF2F5` | 낮은 채도 시안 |

## 5. ⚠ 서로 묶여 있는 제약들 — 하나만 건드리면 다른 게 깨진다

이 목록이 이 문서의 가장 중요한 부분이다. 전부 실측으로 확인한 것이다.

1. **파장을 바꾸면 5개가 같이 움직인다.**
   Gerstner 루프 한계(`1 / Σ A·k`), `surface.steepK`, 바닥 격자 `refract`,
   최상단 마스크 폭, 시뮬 파면 크기(`ambR`/`ambLength`).
   실제로 파장을 5배 줄였을 때 이 다섯이 전부 깨졌다.

2. **Gerstner 루프 한계** `g · Σ(A·k) ≤ 1`. 현재 한계 **0.92**. 넘으면 파가 자기를 말아
   올려 격자가 뒤집힌다. 진폭을 낮추면 한계가 올라간다 (교환 관계).

3. **물리적 `dot(N, L)` 은 이 씬에서 안 통한다.** 파장을 줄이기 전 기울기 중앙값이 0.036 이라
   내적이 0.61~0.69 에서만 움직였다. 그래서 경사의 **방향**과 **세기**를 갈라서 쓴다.

4. **밝기와 색조를 한 덩어리로 묶으면 안 된다.** `mix(bg, warmColor, k)` 를 k>1 로 외삽하면
   어둡게 하는 만큼 색조도 짙어져 "더 어둡게" 가 곧 "더 베이지로" 가 된다.
   실제로 최암부 R−B 가 27(종이의 6.5배)까지 갔었다. 지금은 방향광이 색을 안 섞고
   '높이를 미는' 것으로만 작용한다.

5. **오로라를 경사(`steep`)로 구동하면 안 된다.** 이 바다는 어디나 조금씩 기울어 있어
   화면 100% 가 무지개로 덮여 기름막이 된다. **정규화된 높이**로 구동해야 마루에만 얹힌다.

6. **정규화 기준은 진폭의 합이 아니라 2σ = √(2·ΣA²)** (유의파고 ÷ 2).
   단순 합은 모든 대역이 한 점에 정렬돼야 나오는 값이라 실제로 도달하지 않는다 —
   그걸로 나누면 마루 색이 아예 안 뜬다.

7. **바닥 격자의 밀림(`refract × 기울기`)이 격자 한 칸을 넘으면 안 된다.**
   자기 주기보다 크게 밀면 격자 구조가 남지 않고 뭉개진다.
   그리고 칸 크기는 **근경 기준**으로 잡아야 한다 (화면 맨 아래가 카메라에서 4.5 월드).

8. **블룸이 없으므로 가산 발광을 쓰면 안 된다.** `color += ...` 는 번지지 않고 255 로 잘려
   흰 덩어리만 만든다 (화면의 6.3% 가 터졌었다). 지금은 `mix` 만 쓴다.

9. **GLSL 과 CPU 사본은 같은 `BANDS` 표에서 생성된다.** 배의 부력이 CPU 쪽을 쓰므로
   갈라지면 배가 잠기거나 뜬다. 단 하나의 의도된 비대칭이 Gerstner 역변환이다 —
   GPU 는 정점을 `p + D(p)` 에 놓고, 배는 "월드 X 의 높이"를 물으므로 `p ≈ X − D(X)` 를 푼다.

10. **프레임 게이트가 있다.** 물은 초당 12번, 배는 8번만 갱신된다 (컷아웃 질감).
    물의 형태를 만드는 모든 층은 실시간 `t` 가 아니라 양자화된 `sim.qT` 를 봐야 한다.
    실시간을 쓰는 것은 **빛의 흐름(오로라 위상)뿐**이다.

11. **수면 메시가 0.43 간격이라 파장 1.7 이 하한이다.** 더 잘게 넣으면 기하가 못 따라가고
    반짝임만 남는다.

12. **정반사의 거칠기 신호는 기울기가 아니라 정규화된 파도 높이다.** 정반사는 하프벡터에
    맞는 면만 고르는데 이 구도에서 그 조건이 기울기 ≈ 0.47 하나로 고정된다 —
    빛나는 픽셀은 전부 같은 기울기라 기울기로는 아무리 갈라도 한쪽으로만 간다(실측).

13. **반짝임의 '성격'은 노이즈 셀 크기(`uGlitCalm`/`uGlitRough`)가 만든다.** 로브(`uShine*`)는
    커버리지만 정한다. 잔잔 쪽은 보간된 저주파 노이즈(월드 1/12), 거친 쪽은 양자화된
    고주파(1/70) — 커버리지 13% 로 같을 때 알갱이가 35.9px 대 3.1px 이다.
    ⚠ 잔잔 쪽을 `floor` 로 양자화하면 흰 사각 타일이 된다.

## 6. 지금 풀려는 문제

목표 레퍼런스는 **파도 사이에 배가 앉아 있고, 파도가 배를 가리며 지나가는** 그림이다.
현재는 스케일을 고쳐서 "파도가 파도로" 읽히는 데까지는 왔지만 두 가지가 남았다.

### 문제 A — 마루가 아직 둥글다

가파름 11.9% 는 그래픽 파도 범위(10~15%)에 들어왔는데도 마루가 뾰족하지 않고 돔에 가깝다.
Gerstner 를 더 주면 뾰족해지지만 **루프 한계 0.92** 가 막는다.
진폭을 낮추면 한계가 올라가지만 파도가 낮아진다.

> 묻고 싶은 것 : 정현파 합 + Gerstner 말고, **후처리 없이** 마루를 뾰족하게 만드는 방법.
> (예 : 높이에 비선형 곡선, 마루 근처만 국소 압축, 다른 파형 기저)

### 문제 B — 구도

카메라가 파고의 **3.1배 위**에서 내려다본다(y 2.8, 2σ 0.89). 레퍼런스는 거의 수면 높이다.
카메라를 내리면 레퍼런스 구도가 나오지만 **수영장 바닥 격자가 사라진다** —
스치는 각도에서는 물속이 안 보이는 게 물리적으로 맞고, 그게 `look` 항이기 때문이다.

> 묻고 싶은 것 : 낮은 카메라에서도 물속(바닥 격자)을 유지할 방법,
> 또는 그 둘을 하나의 그림에서 양립시키는 연출.

## 7. 성능 기준선 (Intel Arc iGPU, 120Hz, dpr 2, 1440×731)

| 삼각형 / 선분 | 131,126 / 0 |

성능은 여유가 있다. **지금 문제는 성능이 아니라 아트다.**
