## 한 줄

바다에 돌고래 두 무리가 산다. **뛰는 무리**는 배 뒤 원경에서 1~3번 솟구쳤다 잠수하고,
**유영 무리**는 수면 바로 밑을 등지느러미만 내놓고 빠르게 가로지른다.
**메시 하나 · 재질 하나 · 드로우콜 하나**로 둘 다 그린다.

## ⚠⚠ 시작하기 전에 알아야 할 것 넷

1. **아무것도 커밋 안 됐다.** 전부 작업 트리에만 있다.
2. **같은 작업 트리를 다른 세션이 만진다.** 잠수 전환(`dive.js` · 앱의 `DiveCurtain`)이 그것이고,
   **`main.js` 를 양쪽이 고쳤다.** 커밋할 때 `git add` 를 **파일 단위로** 고른다.
3. **develop 에는 개발 패널이 없다.** 튜닝은 전부 콘솔이다 — `PB.params.podSize = 1.2` 처럼 쓰면
   **다음 프레임에 반영**된다 (`apply()` 불필요). `PB.pod` 로 모듈에 닿는다.
4. **화면으로 판정한다.** 이 작업에서 값을 세 번 잘못 잡았는데 전부 *계산은 맞고 화면이 아니었던* 경우다
   (아래 「함정」).

## 모델 실측 — 이 셋이 설계를 정했다

`Low Poly Dolphin` (mano1creative · Sketchfab). 출처 표기는 3D 담당자와 **이미 정리됐다.**

**① 뼈대는 못 쓴다.** 뼈 6개 중 5개만 쓰이는데 **몸통을 따라가는 뼈가 없다** —
Head 가 z −127..−42 의 정점 150개를 통째로 쥐고(앞 1/3 이 통뼈), Center 는 z 110..117 의 64개,
Tail 은 z 134..143 의 28개뿐이다. 게다가 **정점 75개는 가중치가 0** 이다 (z −48..6.5 · 몸통 중간과 등지느러미).
three.js 의 GPU 스키닝은 가중치 합이 0 이면 그 정점을 원점으로 끌어당기므로, 이 뼈대를 돌리면
**등지느러미가 몸 안으로 함몰된다.** 그래서 스킨 · 애니메이션 · 카메라 · 조명 노드를 다 버리고 메시만 쓴다.

**② 지오메트리도 그냥은 못 휜다.** 길이축 고리가 26개뿐이고 **z 6.5 와 110 사이 108단위(몸 길이의 40%)에
정점이 하나도 없다.** 삼각형 314개 중 136개가 40단위 이상을 걸친다. 휨은 **정점이 있는 자리에서만** 생기므로
그대로 휘면 곡선이 아니라 접힌 자국 하나가 된다. → 로드할 때 **길이축으로 24마디를 낸다** (`sliceZ`).

| | 원본 | 쪼갠 뒤 |
|---|---|---|
| 삼각형 / 정점 | 314 / 317 | **2,558 / 7,674** |
| 길이축 고리 | 26 | **50** |
| 삼각형 최대 걸침 | 43% | **4.2%** |
| 기본 휨에서 이웃 고리 사이 최대 꺾임 | **28.7°** | **9.5°** |

**③ 축은 이미 맞다.** 코가 −z · 등이 +y (Head 뼈가 쥔 정점 z평균 −79.6 / Tail +138.1).
위쪽 래퍼 행렬 두 장이 서로 상쇄돼 항등이라 로컬축이 그대로 월드축이다. 배와 같은 규약(불변식 0-2)이다.

## 구조

```
InstancedMesh 하나 (MAX 26) ── MeshStandardMaterial 하나 (반투명)
  0 .. podCount-1            뛰는 무리   aK.w = 0 (꼬리 세로)
  podCount .. +podSwimCount  유영 무리   aK.w = 1 (꼬리 좌우)
```

인스턴스 속성 둘 (CPU 가 매 프레임 쓴다) :

| | 뜻 |
|---|---|
| `aK` (vec4) | x 공중에 뜬 정도 · y 꼬리질 위상 · z 원경에 녹은 정도 · **w 꼬리질 축** |
| `aQ` (vec2) | x 눕히는 정도(거리별) · y 알파 |

프레임당 GPU 업로드는 26 × (16 + 8 + 64) = **2.3KB** 다.

### 휨은 정점 셰이더가 한다

CPU 로 정점을 갱신하지 않는다 (boat.js 돛 바람과 같은 규율). 길이축 자리 `u`(0 코 ~ 1 꼬리)의
**연속 함수**라 관절 수는 마디 수(24)만큼이고, 단면을 기울기만큼 돌려 몸이 늘어나지 않게 한다.

**⚠⚠ 꼬리질 축이 둘이다.** 뛰는 무리는 **세로**(돌고래는 포유류), 유영 무리는 **좌우**다.
좌우인 이유는 생물학이 아니라 **시점**이다 — 이 카메라는 수면을 내려다보므로 위아래 움직임이
원근에 눌려 거의 안 보인다. 축 하나를 `mix()` 로 섞을 뿐이라 메시도 재질도 하나다.
`aK.w = 0` 이면 예전 세로 식과 **비트 단위로 같다** (무작위 입력 2만 개로 확인 · 오차 0.0).

## 좌표 · 방위 규약

**⚠⚠ 이 씬의 카메라는 배를 따라 돌지 않는다.** `nav.head` 를 90° 돌려도 카메라 방위는 127.9° 그대로다 —
`cameraPose` 가 `PARAMS.camYaw` 로 **씬 좌표에 고정**하고 배만 그 밑에서 돈다.
그래서 무리의 방위를 월드에 무작위로 뿌리면 **화면에서 어디로 갈지가 운에 맡겨진다.**

방위는 **카메라 기준**이다 : `podBearing` 은 *"카메라에서 똑바로 멀어지는 방향"* 에서 몇 도 트는가다.

> 유도 : `cameraPose` 는 카메라를 `look + d·(sin yaw, ·, cos yaw)` 에 놓고 그 점을 본다 →
> 시선(수평) = `−(sin yaw, cos yaw)`. 로컬 −z 가 코이므로 `rotation.y = H` 인 몸이 보는 방향은
> `(−sin H, −cos H)`. **둘이 같아지는 값이 H = camYaw** 다 (실측 −52.1° ↔ 시선 (0.79, −0.61) · 일치).

**⚠⚠ 보는 방향과 가는 방향이 같아야 한다.** 씬 좌표 규약이 `(x − scroll.x, z + scroll.z)` 라
자리를 `+sin H` 로 밀면 몸은 `−sin H` 를 보면서 **옆걸음질**한다. 부호 하나로 갈라진다 —
한 번 그렇게 냈고 사용자가 *"오른쪽으로 이동하고 있음"* 으로 잡아냈다. 지금은 `wx`·`wz` 가 둘 다 `−` 다.

## 도약의 물리 — 넷이 한 묶음이다

**공중에 있는 시간은 중력이 정한다. 손잡이가 아니다.**

```
공중 시간  t = 2√(2 · podHeight / podGravity)
가로 거리  D = podSpeed × t
솟는 각    tan θ = √(2 · podGravity · podHeight) / podSpeed
```

지금 값에서 **t = 0.857s · D = 3.73 · θ = 44.0°** 다. 1 월드 ≈ 1 m 로 읽는다 (배 길이 5.0 = 5m 급).

- 크기 편차가 붙은 마리는 호가 통째로 커지므로 공중 시간도 **√S.sz 배**다 (같은 중력).
  실측 — 최고 높이 0.74 인 마리 0.777s · 1.02 인 마리 0.910s (이론 0.776 / 0.911).
- **각을 유지한 채 빠르게** 하려면 속도와 중력을 **같이** 올린다 (`t ∝ 1/√g`).
- **들어갈 때 꼬리까지 잠긴 뒤에 꺼진다.** 포물선을 양 끝으로 `MARGIN` 만큼 늘리는데,
  그 값을 몸의 반지름에서 푼다 (숫자를 적지 않는다). 실측 — 꺼질 때 수면 위로 남은 높이 **최대 0.027**.

## 규칙 — 두 무리가 공유하는 것과 갈리는 것

### 게이트 (덜 열린 만큼 **물 밑으로 내린다** — 지우지 않는다)

수면이 불투명하게 가려 주므로 경계에서 안 튄다. 알파로 지우면 반투명 유령이 지나간다.

| | 뛰는 무리 | 유영 무리 |
|---|---|---|
| 배 둘레 비우기 | `podNear` 16 | `podSwimNear` 8 |
| 배보다 뒤에서만 | `podBehind` 8 | **안 건다** (지느러미 한 줄이라 화면을 안 가린다) |
| 클로즈업 · 이동 | `hide` (둘 다) | `hide` (둘 다) |

`hide` 는 **main.js 가 값 하나로 넘긴다** — `max(cl, travel.fog)`. `cl` 이 존 구도와 향수 고르기를
이미 합친 클로즈업 블렌드다. 돌고래는 연출을 모른다 (dive.js 와 같은 규율).
화면을 다 덮었다가 걷히면 **시계 원점을 옮겨 처음부터 다시 재생**한다 (이 모듈의 유일한 상태 `_tOff`).

### 거리 규칙 (fade 1 = 가깝다 · 0 = 페이드 끝 · 구간은 `podFade0` 22 → `podFade1` 48)

| 배로부터 | 눕히기 | 알파 | 크기 |
|---|---|---|---|
| 22~28 | 0.41 | 1.00 | 2.76 |
| 32~38 | 0.60 | 1.00 | 3.34 |
| 42~48 | 0.79 | **0.29** | 3.93 |

- **눕히기**(`podFlatNear` → `podFlat`) : 가까우면 빛을 받고 멀수록 납작한 그림자가 된다.
- **알파**(`podFadeOut`) : 페이드의 **마지막 35%** 에서 1 → 0. 색 녹임과 **다른 일**이다 —
  원경색(`uBg`)은 수평선 색이라 중간 거리 바다 위에서는 아무리 녹여도 안 사라진다.
- **크기 보정**(`podSizeFar`) : 페이드 끝에서 +60% 까지. 이 씬의 페이드 구간이 **카메라로부터 58~84** 라
  정직한 원근으로는 몸이 10px 안팎이다.
- **⚠ 페이드 끝은 타일 반지름(`wrapZ`/2 = 50)을 넘을 수 없다.** 거리는 이음매를 건너도 연속이지만
  **자리는 100 만큼 튄다** — 거기서 아직 보이면 순간이동이 보인다. `pod.js` 가 `wrapZ` 에서 잘라 낸다.

### 색 규칙

- **시간대를 따라간다** — `CONFIG.times[i].pod` (times.js 의 규율). 낮은 표가 비어 있어 `podColor` 를 쓴다.

  | | 몸 | 몸 휘도 | 바탕 휘도 |
  |---|---|---|---|
  | 낮 | `#8A8F94` | 0.272 | — |
  | 저녁 | `#6E6A7E` | 0.151 | 0.551 |
  | 밤 | `#232A3E` | 0.024 | 0.056 |

  ⚠ 낮의 회색을 밤에 그대로 두면 몸이 바탕보다 **4.9배 밝아** 실루엣이 뒤집힌다.
- **등·배 배색**(`podBelly`) : 몸 색을 흰 쪽으로 당긴 것이 배 색. **눕히기보다 먼저** 들어간다 —
  눕히기가 이 알베도로 섞으므로 실루엣 상태에서도 배색이 남는다.
- **원경색으로 녹음**(`podHaze` · `podHazeExp`) : 물의 `uBg` 를 **참조로** 받는다 (복사하면 둘째 수평선이 생긴다).

### 리듬

- 뛰는 무리 : `podLeaps` 번 뛰고 `podRest` 주기를 쉰다 (마리마다 1~3). 실측 분포 — 1회 32 · 2회 22 · 3회 12.
  쉬는 구간으로 넘어가는 순간은 이미 물속이다 (한 주기의 그리는 창이 0.83).
- 유영 무리 : `podSwimFin` 만큼 등을 내밀고 `podSwimBob` 이 그 값을 오르내린다.
  음수가 되면 통째로 잠겼다 나온다 — **숨 쉬러 올라오는 리듬이 공짜로 나온다.**
  ⚠ 내민 높이에 **상한**이 있다 (`outMax = 2 × FIN_TOP × 몸길이 × 0.8`) — 없으면 몸이 물 위로 통째로 뜬다.

## 수면 높이 — 물의 거리 LOD 를 같이 본다

물은 카메라에서 멀어질수록 잔물결 대역을 끈다 (water.js 정점 셰이더의 `detail`).
`swellCPU` 는 기본이 `detail 1` 이라 **원경에서 CPU 만 더 높은 수면을 본다** —
그만큼 몸이 떠올라 *"높은 파도에서 유영하는 게 보인다"* 가 된다.

그래서 `createPod(scene, water.uni)` 로 **물의 유니폼 묶음을 참조로** 받아 `uDetail0/1` 을 그대로 읽는다
(카메라 거리 배율 `kD` 와 항공뷰가 이미 들어 있다). 실측 — 두 수면 높이가 최대 **0.085** 어긋났고,
지금은 5,740 표본에서 **물 위로 뜬 경우 0**.

## 안 한 것 — **물속 투과는 만들었다가 되돌렸다**

"바다 속에서 유영하는 모습을 물 너머로 보이게" 를 `submerged.js` 의 **투과 채널**에 얹어 한 번 완성했다.
동작은 했다 (렌더타깃에 실루엣이 또렷이 찍혔고 화면에서도 보였다). **그런데 값이 비쌌다** :

- 패스 하나 추가 · 반해상도 · 배 둘레 `subReach` 안에서만 (8 → 26 으로 올려야 했다)
- 깊이 기준 수면이 배 밑 한 장이라 마리마다 제 수면을 실어야 했다
- **흩는 폭이 수면 바로 밑의 큰 덩어리(선체) 기준**이라, 몸집을 6.5월드까지 키워야 형체가 남았다
  → 물 셰이더에 "흩기를 줄여라" 깃발(파랑 채널)까지 넣어야 했다

사용자 판단 : *"정말 아래에서 유영한다는 느낌을 잘 표현할 필요는 없는데"* → **전부 되돌리고**
지금의 «등지느러미만 내놓기» 로 왔다. 수면 메시가 불투명하고 깊이를 쓰므로 **물이 알아서 가려 준다** —
패스도 드로우콜도 0 이고 거리 제약도 없다.

⚠ 되돌린 자리 : `water.js`(`uSubSoft` · 깃발 · 합성 줄) · `submerged.js`(둘째 패스 · `SUB_LAYER`) ·
`params.js`(`subSoft` · `podDive*` · `subReach` 26 → 8.0). **흔적 0건**을 grep 으로 확인했다.
다시 투과로 가려면 이 문단이 출발점이다.

## 함정 — 이 작업에서 실제로 걸린 것들

1. **중력을 손잡이로 두지 마라.** '주기 중 물 밖에 있는 몫'을 손잡이로 뒀더니 거기서 역산되는 중력이
   **3.5** (실제의 1/2.8)였다. 화면에서는 *"수면에 꼬리를 세우고 서 있는"* 것으로 보였다.
2. **첫 값은 솟는 각이 68.6° 였다.** `tan θ = 4h/D` 를 안 보고 속도·높이를 따로 잡은 탓이다.
3. **`podAmount 0` 이 유영 무리까지 죽였다.** `update()` 맨 앞에서 통째로 `return` 했다.
   지금은 둘 다 0 이어야 쉰다.
4. **`podSwimSpeed` 를 0 가까이 두면 몸이 수직으로 선다** (`atan2` 의 분모). 각을 ±30° 로 잘라 뒀다.
5. **카메라가 배를 따라 돈다고 가정하지 마라** (위 「좌표·방위 규약」).
6. **화면 픽셀은 배로부터의 거리가 아니라 카메라로부터의 거리가 정한다.** 카메라가 배에서 35.8 떨어져 있어
   페이드 구간(배로부터 22~48)이 카메라로는 58~84 다.
7. **범위(`PARAM_RANGES`)가 기본값을 담는지 본다.** `podSpeed` 는 한동안 상한 4 에 기본값 4.35 였다.

`params.js` 의 `pod*` 묶음. 전부 **다음 프레임에 반영**된다.

| 묶음 | 손잡이 |
|---|---|
| 켜고 끄기 | `podAmount` · `podSwim` (0 = 비트 단위 롤백) |
| 머릿수 · 흩기 | `podCount` 20 · `podSwimCount` 6 · `podGroups` 6 · `podSpread` 5 |
| 방위 | `podBearing` 55 · `podBearingVary` 30 |
| 도약 | `podGravity` 9.8 · `podSpeed` 4.35 · `podPeriod` 1.8 · `podHeight` 0.9 · `podLeaps` 3 · `podRest` 2 |
| 유영 | `podSwimSize` 0.45 · `podSwimSpeed` 3.5 · `podSwimBeat` 2.2 · `podSwimFin` 0.22 · `podSwimBob` 0.3 · `podSwimPeriod` 4 · `podSwimNear` 8 |
| 휨 | `podBendAmp` 0.10 · `podBendWaves` 1.15 · `podBendExp` 2.2 · `podBeats` 3 · `podBendAir` 0.35 |

### 콘솔 상용구

```js
PB.params.podAmount = 0;              // 뛰는 무리만 끈다
PB.params.podSwim = 0;                // 유영 무리만 끈다
PB.params.sceneTime = 2;              // 밤 — 실루엣이 안 뒤집히는지 본다
PB.params.podSize = 1.4;              // 크게 띄워 형태·휨을 확인
// 배를 무리 옆으로 옮긴다 (유영 무리 기준 · 뛰는 무리는 children[0] 의 앞 20칸)
(()=>{const d=PB.pod.group.children[0],a=d.instanceMatrix.array;PB.nav.speed=0;let b=null;
for(let x=-50;x<50;x++)for(let z=-50;z<50;z++){PB.pod.update(PB.sim,{scroll:{x,z:-z},cam:PB.cam,hide:0});
let v=0,n=99;for(let i=0;i<d.count;i++){const k=i*16;if(Math.hypot(a[k],a[k+1],a[k+2])<.01)continue;
const q=Math.hypot(a[k+12],a[k+14]);if(q>20)continue;v++;n=Math.min(n,q)}
const s=Math.abs(n-12)-v*4;if(v>=3&&(!b||s<b.s))b={s,x,z:-z}}
if(b){PB.nav.scroll.x=b.x;PB.nav.scroll.z=b.z}return b})()
```

## 다음에 할 만한 것

1. **CHANGELOG · 버전** — 아직 안 적었다. 잠수 작업과 커밋이 섞이지 않게 파일 단위로 나눠 담는다.
2. **수면 물결 자국(V자 항적)** — 유영 무리가 지느러미로 물을 가르는 자국. 물 셰이더에 항 하나다.
   지금 유영 무리가 *작은 검은 자국*으로만 읽히는 것을 가장 크게 보완할 수 있는 한 수로 본다.
3. **역광 림** — 이 씬은 대부분 역광이라 테두리만 밝히면 실루엣이 산다.
4. **개체별 색 미세 편차** — 지금은 무리가 똑같은 한 색이다. `aQ` 에 성분 둘이 남아 있다.
5. **`podSwim` 의 읽힘** — 페이드 구간이 카메라로부터 58~84 라 등 0.5월드가 10px 안팎이다.
   `podSwimFin` 을 올리면 등이 더 나오지만 "수면에 떠 있는" 쪽으로 기운다. 2번이 더 나은 길로 보인다.
