## 0. 이번 요구사항과 문서의 우선순위

사용자 요구: **현재 바다의 색상 컨셉을 유지하고, 그 밖의 파도 운동·바람·중력·빛·거품은 실제 바다를 목표로 한다.**

이 문서는 기존 `파도-표현-개선안.md`를 보완한다. 이전 문서는 컷아웃 리듬과 장식적 마루 표현을 상당 부분 유지하는 개선안이었다. 이번에는 **물리적 인과관계가 우선**이다. 따라서 아래 제안 중 시간 게이트·거품 이동·발광의 변경은 새 목표에 따른 설계 변경이며, 기존 구현이 당시 지시를 어겼다는 뜻이 아니다.

다음 경계를 명확히 한다.

- **색상 고정:** 검토 시점 `CONFIG.color`, `colorDeep`, `waterTone=0.35`를 기준으로 보존한다. 과거의 `waterTone=0`으로 되돌리거나 바다를 진한 파랑으로 바꾸는 처방을 하지 않는다.
- **광학은 개선 대상:** 반사 위치·밝기 변화·투과·거품 대비는 실제 계산 결과로 바뀔 수 있다. 색상 컨셉을 고정하는 것과 기존 모든 픽셀의 RGB를 고정하는 것은 다르다.
- **물리 검증과 최종 색 표현을 분리:** 물의 운동·가시성·반사 강도를 먼저 계산하고, 승인된 색상 표현을 별도 단계로 적용한다. 색을 위해 파도의 힘이나 거품 이동속도를 바꾸지 않는다.
- **정확성의 범위:** 실시간 스펙트럼 수면은 자연스러운 근사다. 쇄파 내부의 공기·기포·난류까지 실제 바다와 완전히 같은 유체 계산은 아니다. 계산하지 않는 현상은 계산한 것처럼 설명하지 않는다.

이번 문서의 분류는 **물리 근거 / 현재 코드 확인 / 구현 제안 / 미검증**이다. 새 코드의 시각·성능 개선은 아직 실측하지 않았다.

## 3. 단위와 시간 — 물리식보다 먼저 고정할 계약

### 3.1 계산은 미터·초로 통일한다

```text
ℓ = metersPerWorldUnit
위치_m = 위치_world × ℓ
진폭_m = 진폭_world × ℓ
파수_m = 파수_world / ℓ
속도_m/s = 속도_world/s × ℓ
시간 = 실제 초
g = 9.81 m/s²
```

배 길이 약 2.48 월드 단위가 실제 몇 m를 뜻하는지 정해야 한다. 종이배를 작게 보여 주는 카메라와 수십 m 길이의 배에 해당하는 파도 속도를 혼합하면 장면의 무게감이 어긋난다. 아직 물리 크기는 확정하지 않았으므로 이 문서의 1m/world 예시는 **검산용 가정**이다.

1m/world, 파장 3.2m, 심해 중력파 가정에서 직접 계산한 값:

| 항목 | 결과 |
|---|---:|
| 실제 분산관계의 위상속도 | 약 2.235m/s |
| 해당 파도의 주기 | 약 1.432초 |
| 현재 0.62×0.48 배율의 주기 | 약 4.811초 |

현재 배율을 무조건 “틀린 중력”이라고 부르지는 않는다. 시간 감속 없이 같은 배율을 물리 길이로 해석하면 약 11.29m/world가 필요하다. 그러면 배도 약 28m 규모가 된다. **속도·길이·중력을 동시에 일관되게 고르는 것이 핵심**이다.

구현 제안: `ocean-state.js` 또는 `config.js`에 물리 상태를 정의하고, 현재 `waveSpeed`는 물리 모드에서 1에 해당하는 실제 초 기준으로 대체한다. 슬로모션은 별도 비교 모드로 남기며 실제 운동 검증에는 사용하지 않는다.

### 3.2 12Hz의 물리 결과를 그대로 계단처럼 표시하지 않는다

현재 12Hz·8Hz는 당시 표현 목표에 맞는 선택이다. 그러나 색상 외의 실제 운동을 목표로 하는 이번 검증에서는 변경 후보가 된다.

- 해석적 파도: 매 렌더 프레임의 동일한 `t`에서 높이·법선·변위·수면 속도를 평가한다.
- 국소 솔버·강체: 고정 `dt`로 적분하고 렌더 상태를 일관되게 보간한다.
- 거품: 생성·감쇠를 초 단위로 정의한다. 표시 프레임에 따라 수명이 달라지지 않게 한다.
- 큰 `dt`가 들어오면 따라잡기·일시정지 정책을 명시한다. 일부 계산만 시간을 버리면 파도·거품·배가 분리된다.

단순히 슬라이더를 전부 60으로 올리는 작업이 아니다. 시뮬 실행 비용, GPU 읽기, 표시 시간의 계약을 함께 바꾼다.

## 4. 파도가 움직이는 수학

### 4.1 중력·압력·관성

작은 진폭·비회전 흐름의 표면 중력파는 아래 관계를 출발점으로 삼는다. 물은 거의 비압축성이며, 속도 퍼텐셜과 수면 경계조건으로 운동을 기술한다. 이 근사는 쇄파 내부의 난류까지 설명하지 않는다. [MIT][M1]

```text
∇²φ = 0                         // 유체 내부
∂η/∂t = ∂φ/∂y                  // 평균 수면에서 선형화
∂φ/∂t + gη = 0                 // 평균 수면에서 선형화

ω² = g k tanh(kd)
```

`η`는 평균 수면으로부터의 높이, `d`는 수심이다. 수면에 `-g·dt²`를 직접 더하는 낙하 애니메이션으로 바꾸지 않는다.

더 짧은 물결까지 명시적으로 다룰 때는 표면장력 항을 포함한다.

```text
ω² = (gk + σs k³/ρ) tanh(kd)
```

이 식의 적용 범위와 표면장력·중력의 역할은 [MIT 분산관계 강의][M2]를 따른다. 단위계는 전부 SI로 유지한다.

### 4.2 서로 다른 파동은 더해진다

```text
φi(x,t) = ki · x - ωi t + phasei
η(x,t) = Σ Ai cos(φi)
```

작은 진폭에서 마루끼리는 더해지고 마루·골은 상쇄된다. 큰 파도가 만들어졌다고 작은 파동 성분을 삭제하지 않는다. 큰 파도끼리도 중첩될 수 있으며, 그 집중이 지나가면 낮아질 수 있다. [NOAA 이상파 설명][N2]

현재 `envRHi/envRLo`로 큰 파도 세기와 잔물결 세기를 반대로 묶는 규칙은 물리법칙이 아니다. 원거리 너울과 현지 바람파를 각각 유지하고, 실제 에너지 소산이 일어난 성분만 약하게 만드는 방향이 적절하다.

### 4.3 파도 묶음은 별도 느린 노이즈 없이도 생긴다

같은 방향의 가까운 두 주파수 성분을 더하면:

```text
A cos(k1x - ω1t) + A cos(k2x - ω2t)
= 2A cos((Δk x - Δω t)/2) cos(k̄ x - ω̄ t)

묶음의 속도 ≈ Δω/Δk → dω/dk
```

이는 위 합성식에서 직접 유도한 결과다. 심해 중력파에서는 `cg=cp/2`이지만, 다방향 파도 묶음이 모두 하나의 평균 방향·속도로 이동하는 것은 아니다.

수정 제안: `swellEnv()`는 기준선으로 남기되 물리 비교 모드에서는 `envAmount=0`과 스펙트럼 합성을 비교한다. 부족한 군파를 이유로 임의 포락선을 곱하기 전에 파장 분포·위상·에너지 분포를 확인한다. 포락선을 사용한다면 근사 항임을 표시하고 에너지와 모든 미분에 반영한다.

## 5. 바람 — 파도 속도를 올리는 손잡이가 아니다

### 5.1 입력 상태

```js
// 새 설계의 자료형 예시. 아래 파일·필드는 아직 구현되지 않았다.
const seaState = {
  metersPerWorldUnit,
  waterDepthM,
  windSpeed10m, windDirection,
  windFetchM, windDurationS,
  windSea: { significantHeightM, peakPeriodS, gamma, spread },
  swell:   { significantHeightM, peakPeriodS, direction, spread },
  currentVelocityMps,
  seed
};
```

풍속 하나로 파고·주기·방향 분포가 유일하게 결정되지는 않는다. 얼마나 오래, 얼마나 넓은 구간에서 불었는지와 외부에서 온 너울이 함께 작용한다. 처음에는 물리적으로 타당한 고정 바다 상태를 입력받고, 바람이 바다를 성장시키는 계산은 별도 단계로 둔다. [NOAA 발생 설명][N1], [WAVEWATCH III][N3]

### 5.2 스펙트럼으로 성분의 진폭을 결정한다

첫 구현 후보는 풍랑용 JONSWAP과 원거리 너울의 별도 분포다. 다음은 **Hz 단위의 한쪽 주파수 스펙트럼** 표현이다.

```text
S(f) = αg² / ((2π)⁴ f⁵)
       · exp[-1.25(fp/f)⁴]
       · γ^r
r = exp[-(f-fp)² / (2 s² fp²)]
s = 0.07 (f≤fp), 0.09 (f>fp)
fp = 1/Tp

S(f,θ) = S(f) D(θ|f)
∫ D(θ|f) dθ = 1
```

스펙트럼 모양과 정규화는 [wavespectra 공식 구현][S1]과 대조한다. `γ=3.3`을 모든 바다에 고정 적용하지 않고 파도의 발달 상태에 맞춰 선택한다.

방향 분포의 초기 후보는 `D∝cos^(2sθ)((θ-θ0)/2)`처럼 정규화 가능한 분포로 둔다. 방향 차이는 `[-π,π]`로 감싸고 `sθ≥0`으로 설정한다. 이는 구현 후보이며 보편적인 해양 법칙은 아니다. 큰 너울과 짧은 풍랑에 같은 방향 분포 폭을 강제하지 않는다.

이산화는 다음과 같이 진행한다.

```text
Δm0_ij = S(fi,θj) Δfi Δθj
Aij = sqrt(2 Δm0_ij)
phaseij = 고정 시드에서 추출한 균등 난수 [0,2π)
m0 = Σ Δm0_ij
Hm0 = 4 sqrt(m0)
```

목표 유의파고 `Hm0`가 주어지면 총분산이 `(Hm0/4)²`이 되도록 전체를 정규화한다. 큰 파도 성분을 추가할 때마다 총에너지가 무제한 증가하지 않게 한다. Hz·각주파수·파수 스펙트럼을 혼용하지 않고, 변수 변환 시 야코비안을 포함한다. 주파수 처리와 매개변수 단위는 [wavespectra][S2]를 참고한다.

### 5.3 바람 변화는 에너지 변화를 거쳐 반영한다

```text
∂N/∂t + ∇x·(cg N) + ∇k·(kdot N) = S_total / ω
N = E/ω
S_total = S_wind + S_nonlinear + S_dissipation + ...
```

이는 파동 작용량의 수송·입력·소산을 구분하는 개략식이다. NOAA 모델 전체의 좌표계·소스 항을 이 한 줄로 구현했다는 뜻은 아니다. [WAVEWATCH III][N3]

웹 구현에서는 먼저 고정 스펙트럼의 정상 바다를 사용한다. 바람 변화가 필요해지면 진폭이 아니라 성분 에너지의 목표값을 완만하게 갱신한다. 단순 완화식은 시각적 근사이며 실제 풍랑 발달 모델과 구분한다. `Math.random()`으로 매 프레임 위상·방향을 재설정하지 않는다.

## 6. three.js에서 수면을 만드는 구조

### 6.1 공통 평가 결과

```text
sampleOcean(positionM, timeS) →
  heightM, displacementM,
  dHeightDx, dHeightDz,
  displacementJacobian,
  surfaceVelocityMps,
  breakingSource
```

수면, 거품, 배가 같은 상태를 읽는다. GLSL·TSL·CPU에 서로 다른 대역 상수를 복사하지 않는다. 현재 `swell.js`의 공통 정의 방식을 확장한다.

### 6.2 직접 합성과 FFT의 역할

- 직접 합성: 소수 성분으로 식·좌표·시간·법선을 검증하기 쉽다. 검산 기준으로 유지한다.
- FFT/IFFT: 많은 성분의 높이·변위·미분 격자를 효율적으로 합성한다. 별도의 물리법칙이 아니다.
- 현재 소수 성분의 생산용 대체에 몇 개가 충분한지는 미정이다. 이전의 “대역 수만 늘려도 해결되지 않았다”는 기록을 반영해, 직접 합성 성분 수의 증가를 완성안으로 단정하지 않는다.

FFT를 선택하면 다음 규약부터 검증한다. [Tessendorf][T1]

```text
k(n,m) = (2πn/Lx, 2πm/Lz)
η̂(k,t) = h0(k)e^(-iωt) + conjugate(h0(-k))e^(+iωt)
η(x,t) = Σ η̂(k,t)e^(+ik·x)         // 사용 중인 DFT 정의를 고정
∂η/∂x = IFFT(i kx η̂)
∂η/∂z = IFFT(i kz η̂)
```

실수 표면을 위한 켤레 대칭, DC·Nyquist 성분, FFT 정규화, 주파수 인덱스 배치, 진행 방향을 단일 모드 테스트로 확인한다. `h0`의 분산과 ±k 중복에 따른 배율은 라이브러리 규약에 맞춰 `var(η)=m0`로 검산한다. 이 식만 복사해 진폭이 맞는다고 가정하지 않는다.

다중 스케일 타일은 대역별 에너지를 분배한다. 겹치는 대역을 두 번 합쳐 파고가 커지지 않게 하고, 타일 반복성도 검사한다. 바람 변화에 따른 실제 비선형 에너지 전달은 FFT만으로 생기지 않는다.

### 6.3 변위된 표면의 법선

```text
P(p,t) = (px + Dx, H, pz + Dz)
J = I + ∂D/∂p
Tx = (1+Dx,x, Hx, Dz,x)
Tz = (Dx,z, Hz, 1+Dz,z)
Ngeom = normalize(cross(Tz,Tx))
```

이는 현재 좌표계에서 직접 유도한 접선·법선이다. `∇p H`를 그대로 변위 후 월드 기울기로 취급하지 않는다. 기존 포락선을 유지하는 비교에서는 `D`에 곱해진 포락선의 미분도 포함한다. 필요하면 `∇X H=J⁻ᵀ∇pH`를 사용한다.

변위의 부호는 단일 코사인파의 높은 마루에서 정점이 모이고, 골에서 벌어지는지 확인한다. `det(J)>0`만으로 모든 국소 뒤집힘을 배제하지 못하므로 최소 특이값, 대칭인 경우 최소 고유값도 검사한다.

현재 `water.js`의 기울기 8배·미세파 3배·반사용 별도 배율은 물리 기준 비교에서는 제거 대상으로 둔다. 법선이 작아서 변화가 안 보이면 빛의 분포·공간 해상도·파도 규모를 확인하고, 법선을 과장해 다른 물체처럼 반사시키지 않는다.

### 6.4 기하·법선·거칠기의 대역 분리

| 화면에서 분해 가능한 크기 | 처리 |
|---|---|
| 큰 너울·주파도 | 메시 변위·부력 |
| 메시보다 작지만 픽셀에서 보이는 잔결 | 미세 법선 |
| 한 픽셀보다 작은 잔결 | 평균 기울기 분포·거칠기 |

같은 성분을 기하와 법선에 중복으로 더하지 않는다. 원경에서 잔결을 없애고 기울기 분산까지 0으로 만들지 않는다. 사라진 상세를 반사 분포로 넘기는 접근은 [Bruneton·Neyret·Holzschuch의 연구][L4]를 참고한다.

`microA/B`는 현재 높이 진폭이 아니라 기울기에 직접 곱해진다. 새 스펙트럼의 `Ak`와 중복 적용되지 않게 한다. `vMat`, 실제 `X`, `qScroll` 중 어느 좌표에서 평가하는지도 명시한다.

## 7. 쇄파와 거품 — 움직이는 사건과 물 위에 남는 물질

### 7.1 파도와 함께 움직이는 흰 부분은 만들 수 있다

v0.11.3 이후 `foamDrift=1`은 사용자의 이전 “서퍼처럼 파도와 함께”라는 요청을 반영한다. 이번의 실제 물리 목표에서는 이를 아래 두 현상으로 해석하는 편이 적절하다.

- **활성 쇄파:** 마루 근처에서 계속 새로 부서지는 사건. 발생 위치가 파도를 따라 진행한다.
- **잔류 거품:** 이미 생긴 기포가 물 위에 남아 이동·소멸하는 물질.

활성 부분은 마루를 따라 하얗게 진행하면서도 뒤에 잔류 거품을 남길 수 있다. 전체 거품 텍스처를 마루 속도로 옮길 필요는 없다.

### 7.2 생성 소스

현재 높이·앞면 게이트를 기준선으로 보관하고, 변위의 압축에서 생성 후보를 만든다.

```text
B = 1 - smoothstep(jLow, jHigh, det(J))
```

이것은 기하 압축을 이용한 **쇄파 대리 모델**이다. 진짜 물리의 보편적인 쇄파 임계값은 아니며, 뒤집힌 격자를 만들어야 거품이 생기는 방식으로 사용하지 않는다. [Whitecaps 논문][F1]

물리 기반 검증에서는 다음 조건이 필요하다.

- 평면 `J=I`에서 생성 0.
- 높은데 완만한 너울은 반드시 거품을 만들지 않음.
- 낮아도 국소적으로 압축된 파면은 후보가 될 수 있음.
- 앞면 방향은 국소 진행 방향에 따른다. 다방향 파도 전부에 평균 방향 하나를 강요하지 않음.
- 선체 충돌과 배 주변 교란은 별도 소스를 가진다.

`uFoamHigh`의 높이 임계 하나나 정규파의 `H/λ≈1/7` 하나로 다방향 불규칙파 전체를 판정하지 않는다. 후자는 제한된 조건의 가파름 기준이지 범용 픽셀 거품 생성식이 아니다.

### 7.3 활성·잔류의 두 상태

다음은 제안하는 유계의 반응·이류 근사다. 실제 기포 질량 방정식이 아니다.

```text
(∂t + u·∇) A = kb B (1-A) - A/τa
(∂t + u·∇) R = kr A (1-R) - R/τr

A: 활성 거품 점유도
R: 잔류 거품 점유도
τa < τr
```

발생 소스 `B(x,t)`가 마루와 함께 진행하므로 짧은 수명의 `A`가 마루를 따라 보인다. `R`은 그 뒤에 남는다. `A`와 `R` 모두 물질을 운반하는 유속으로 이류한다.

반응식 `dF/dt = b(1-F)-dF`를 서브스텝 동안 일정 계수로 근사하면:

```text
F_eq = b/(b+d)
F_next = F_eq + (F_adv-F_eq) exp[-(b+d)dt]
```

`b+d=0`일 때는 값을 유지한다. 이 식은 단순 Euler보다 범위 0~1을 유지하기 쉽다. 활성→잔류 결합은 고정 스텝으로 처리하고 스텝 수를 바꿔 수렴성을 검사한다.

현재 `.w` 한 채널을 기준선으로 유지하고, 필요하면 `foam-state.js`에 별도 RG16F 핑퐁 상태를 둔다. 640²·2채널·half float·2장은 약 **3.125MiB**이며 부가 리소스는 제외한 값이다. WebGL에서의 해당 포맷 렌더 가능 여부는 실제 장치에서 확인한다. `.x/.y/.z`의 의미를 재사용하지 않는다.

### 7.4 거품 이동의 좌표 계약

```text
실제 위치 X = p + D(p,t)

물리 위치 X 격자에 저장: dX/dt = u_surface
매개변수 p 격자에 저장: dp/dt = J⁻¹(u_surface - ∂D/∂t)
```

이는 좌표 미분에서 직접 나온 관계다. 메시가 이미 수행하는 궤도 운동을 거품 이류에 다시 더하지 않는다. 항해 원점 이동도 한 번만 적용한다.

참고로 단일 소진폭 심해 진행파의 표면 Stokes drift 규모는 `Us≈ωkA²`이며 방향은 파의 진행 방향이다. `Us/cp≈(kA)²`이므로 **항상 위상속도의 0.1배라는 법칙은 없다.** 혼합파·수심·해류를 포함하는 경우에는 해당 모델에서 유속을 계산한다. 기존 코드의 `foamDrift=0.1`은 물리 검증된 기본값으로 복사하지 않는다. [Tessendorf의 입자 운동 설명][T1]

### 7.5 거품 외형과 빛

기존 Worley·워프는 미세 외형 생성에 재사용할 수 있다. 다만 `A/R`이 없는 곳에서 거품을 만들거나 상태 이동과 무관하게 패턴만 이동시키지 않는다.

- 새 거품: 촘촘하고 불규칙한 밀도.
- 잔류 거품: 물의 흐름을 따라 조각·구멍으로 약해짐.
- 오래된 거품: 개별 경계가 약해지고 소멸.
- 원경: 흰 선을 억지로 두껍게 유지하지 않고 평균 점유율로 전환.

노이즈에 “소멸하는 물리”의 역할을 맡기지 않는다. 밀도·수명은 상태 방정식, 노이즈는 그 안의 작은 형태를 담당한다.

현재처럼 `face/liveH`가 누적 거품 전체를 다시 강하게 자르면, 파도가 지나간 뒤에도 남아야 할 거품이 다음 파도의 경사에 따라 켜지고 꺼질 수 있다. 앞면 조건은 우선 **생성 소스**에 적용하고, 잔류 표시에는 같은 조건을 반복 적용하지 않는 비교가 필요하다.

## 8. 빛 — 밝은 색을 칠하는 대신 물의 경계면을 계산한다

### 8.1 프레넬

공기→물의 굴절률을 근사적으로 1과 1.333으로 두면 수직 입사 반사율은 약 0.02037이다. 시선이 수면을 스칠수록 반사가 강해진다. [PBRT][L1]

```text
F0 = ((n_air-n_water)/(n_air+n_water))²
F(cosθ) ≈ F0 + (1-F0)(1-cosθ)⁵       // Schlick 근사
```

현재 `pow(1-dot(N,V),3)`를 투과색의 혼합 계수로 쓰는 방식은 이 에너지 분배와 다르다. 기준 구현은 정확한 dielectric Fresnel 또는 검증한 Schlick 근사를 사용한다. 미세면 정반사의 프레넬 인자는 `V·H`를 사용하며, 매크로 법선의 `V·N`과 혼동하지 않는다.

### 8.2 태양·하늘·주변 물체

깨끗한 수면은 광원의 방향과 표면 법선에 따라 반사한다. 주반사 모델의 후보는 GGX 미세면이다. 이는 물 표면 통계의 근사이며 모든 바다의 정확한 기울기 분포는 아니다. [PBRT 미세면 모델][L2]

```text
fr(L,V) = D(H) F(V·H) G(L,V) / (4 (N·L)(N·V))
H = normalize(L+V)
D_GGX = α² / {π[(N·H)²(α²-1)+1]²}
```

여기서 `D`는 수평 변위와 이름만 같은 법선 분포 함수이므로 실제 코드에서는 `ndf` 등으로 구별한다. 분모의 epsilon, 같은 반구 조건, masking/shadowing, roughness→α 변환을 일관되게 구현한다.

구현 변경:

1. `water.js`의 `pow(dot(Ns,H),shine)`를 기준 BRDF와 비교한다.
2. 태양은 작은 각도 크기를 가진 광원으로 다룬다. 태양과 하늘 환경광을 분리하고 같은 태양 에너지를 이중 합산하지 않는다.
3. 하늘을 화면에 그리지 않더라도 **반사에 사용할 방향별 하늘 조도**는 필요하다. 흰 배경색 하나를 모든 방향의 동일한 빛으로 대체하면 반사 변화가 약해진다.
4. 실루엣·큰 파도에 의한 가림은 미세면 `G`만으로 해결되지 않는다. 필요하면 수면 self-shadow를 별도 근사로 추가한다.
5. `reflect.js`의 반사용 fill light, 반사상 임의 확장·절단을 물리 기준 화면에서는 분리한다. 동일 물체는 동일 광원 아래에서 보여야 한다.

`scene.environment`를 지정했다고 현재 커스텀 ShaderMaterial이 자동으로 환경 반사를 계산하지 않는다. 해당 셰이더에서 명시적으로 샘플하거나 적절한 물리 재질·노드 구조로 옮겨야 한다.

### 8.3 굴절·수중 경로

```text
R = reflect(I, Nshade)
T = refract(I, Nshade, n_air/n_water)
Tr(ℓpath) = exp(-σt ℓpath)
```

`I`는 카메라에서 표면으로 향하는 단위벡터다. 위 `T`는 공기에서 물로 들어가는 경우이며, 물속 카메라는 법선·굴절률 비율과 전반사 조건을 바꿔야 한다. 경로 길이 `ℓpath`는 월드 y 깊이가 아니라 실제 물속 광선 거리다. 투과 감쇠의 근거는 [PBRT 매질 투과][L3]다.

`submerged.js`와 `water.js`의 잠긴 선체는 다음 순서로 검증한다.

- 같은 수면 위치·법선에서 굴절 광선을 만든다.
- 광선과 물체의 교차 또는 명시적 깊이 버퍼 근사로 경로를 구한다.
- 거리가 길어질수록 지수 감쇠한다.
- 정확한 교차를 하지 않는 화면 공간 굴절은 가려짐·화면 밖 정보의 한계를 표시한다.

수면 높이만으로 시안색·흰색을 덧칠하는 것을 투과의 물리 모델로 부르지 않는다.

### 8.4 거품은 깨끗한 물과 다른 반사 성격이다

```text
C = (1-W) C_clear + W C_foam
```

`W`는 필터링한 거품 점유율이다. 거품은 빛을 여러 번 산란시켜 넓고 부드럽게 반사하는 근사로 표현한다. 깨끗한 수면의 날카로운 하이라이트를 거품 위에 그대로 다시 더하지 않는다. [Whitecaps의 거품 반사 근사][F1]

### 8.5 색상 컨셉을 유지하는 방법

팔레트는 보존하고, 물리 출력의 다음 항을 별도 확인한다.

```text
물리: 반사 강도·방향, 투과량, 가림, 거품 점유율
색상 표현: 승인된 진주색·보라·블루의 색조 매핑
```

보라·블루가 깨끗한 일반 바다에서 자연적으로 생기는 마루색이라고 주장하지 않는다. 사용자 컨셉에 따른 **색상 단계의 예외**로 둔다. 그 색 때문에 발광을 만들거나 높은 마루 전체를 흰 리본으로 바꾸지 않는다.

`seam/glow`가 물 자체의 발광처럼 보이는 부분은 제거·축소 비교 대상이다. 물은 일반적으로 스스로 빛을 내지 않는다. 카메라의 bloom을 쓸 경우에도 실제 밝은 반사광에서 파생되어야 한다.

선형 공간에서 조명·혼합을 계산하고 출력 변환은 한 번만 한다. 팔레트 텍스처와 법선·높이·거품 데이터의 색 공간도 구분한다. [three.js Color Management][J1]

팔레트 보존이 밝기를 거의 한 값으로 압축하는 조건까지 뜻한다면, 남길 수 있는 명암 단서에도 한계가 생긴다. 이 문서는 기존 파랑으로의 교체나 `waterTone` 증대를 해결책으로 사용하지 않으며, 먼저 같은 팔레트 안에서 물리적인 반사 분포를 검증한다.

## 9. 국소 파동 솔버와 선체 반응

### 9.1 현재 sim.js는 바다 전체의 중력파 솔버가 아니다

현재 식은 대략 다음 계열이다.

```text
v ← damping · (v + C · discreteLaplacian(h))
h ← h + v
```

장파장 연속 극한에서는 `ηtt≈c0²∇²η` 형태의 파동방정식에 대응한다. 이 경우 `ω≈c0 k`이며 심해 중력파의 `ω²=gk`와 다르다. 격자 수준에서는 수치적 분산도 추가된다. **“실제 파동방정식”이라는 설명만으로 실제 바다의 분산관계까지 맞는 것은 아니다.** 이 비교는 현재 이산식에서 유도한 것이다.

제안:

- 원거리 바다는 스펙트럼 모델로 담당한다.
- 현재 솔버는 국소 항적·접촉의 근사로 유지하되, 별도 효과임을 명시한다.
- 파면을 임의 생성하는 ambient 항이 전체 바다의 움직임을 지배하지 않게 한다.
- 국소 파동까지 중력파 분산을 맞춰야 한다면 `ηtt+g|∇|tanh(d|∇|)η=S` 계열의 선형 표면파 연산자를 검토한다. 표면장력이 필요하면 해당 항을 추가한다.
- 기존 `sim.c`, damping, 스펀지를 임의로 조정해 실제 중력처럼 보이게 하지 않는다. 솔버 교체는 별도 범위로 검증한다.

### 9.2 배는 힘과 토크에 반응한다

현재 `boat.js`는 수면 높이를 읽고 자세를 제한·보간하며 위상을 앞당긴다. 실제 강체 부력 적분은 아니다.

```text
Fbuoy = ρ g Vsub · up
Fgravity = m g · down
m dv/dt = Fbuoy + Fgravity + Fdrag + Fexternal
τbuoy = (centerOfBuoyancy - centerOfMass) × Fbuoy
I dΩ/dt + Ω × (IΩ) = Στ
```

이것은 강체·정수압 근사를 프로젝트에 적용하는 제안식이다. 빠른 쇄파 충격·added mass·선체 주변 유체를 전부 푸는 식은 아니다.

첫 단계는 폐합된 부력용 선체 프록시 또는 부피를 분담하는 부력 표본으로 잠긴 부피·부심을 추정하는 것이다. 종이배의 보이는 메시를 그대로 수밀한 선체로 간주하지 않는다. 항력은 물과 배의 상대속도에 걸고, 회전은 토크·관성·감쇠로 적분한다.

`rightLead`를 “실제 배는 항상 미리 내려간다”는 물리법칙으로 남기지 않는다. 물리 모드에서 임의 sin·선행·각도 포화는 힘 모델과 분리해 비교한다. 안전용 각도 제한과 실제 복원력을 같은 것으로 취급하지 않는다.

`swellCPU()`의 역좌표는 `p+D(p)=X`를 풀고 오차 기준을 둔다. FFT에서는 GPU 표면과 동일한 표본을 조회해야 한다. 비동기 읽기에는 시간표시를 붙이며, 늦은 높이를 현재 파도인 것처럼 사용하지 않는다.

## 12. 수학·화면·성능 검증

### 수학적 기준

| 시험 | 통과 조건 |
|---|---|
| 단일 진행파 | 지정 방향, `cp=ω/k`, 위상·진폭 오차를 수치 보고 |
| 두 근접 파동 | 묶음 이동이 `Δω/Δk`와 대응 |
| 중첩·상쇄 | 선형 모드에서 합성 결과가 개별 합과 일치 |
| 스펙트럼 분산 | 충분한 공간·시간 표본에서 `var(η)`가 목표 `m0`에 수렴 |
| FFT 실수성 | 켤레 대칭·허수 잔차·DC·진폭 정규화 확인 |
| 법선 | 해석 미분과 변위 표면 유한차분이 수렴 |
| 무쇄파 평면 | 거품 생성 0, 기존 거품은 수명에 따라 감소 |
| 활성·잔류 | 생성 소스는 파면을 따라가고 잔류는 물 유속을 따름 |
| 반사 | 수직에서 F≈0.02037, 스침각에서 증가, 에너지 중복 없음 |
| 투과 | 경로 증가에 따라 감소, 0거리 Tr=1 |
| 평수 부력 | 정지 평형에서 평균 부력≈중량, 불필요한 자체 sin 없음 |
| 시간 독립성 | 같은 시간·동일 입력에서 30/60/120Hz 표시가 같은 상태를 가리킴 |

허용 오차는 물리 길이·해상도·출력 정밀도를 정한 뒤 수치로 고정한다. 아직 재현하지 않은 실험에 “통과”라고 적지 않는다.

### 시각 검증

- 기본·항공·자유 시점, 서로 다른 파도 상태 4개 이상.
- 기본 팔레트 고정. 별도 디버그에서만 무채색·법선·반사·거품을 확인한다.
- 선단/후단은 단일 진행파의 실제 이동으로 확인한다. “화면에서 내려가는 면”과 혼동하지 않는다.
- 해석적 시각뿐 아니라 국소 시뮬의 시드·초기 상태·스텝 수까지 고정한다.
- 파도의 연속 띠가 줄었는지만 보지 않는다. 실제 너울도 길게 이어진다. 반사의 반응과 거품 생애가 자연스러운지를 함께 본다.

### 성능·범위

- 현재 장치·해상도·DPR에서 파도 평가, 거품, 수면 렌더, GPU 읽기의 평균·p95를 각각 재측정한다.
- 실제 주기와 12Hz 게이트를 섞은 상태에서 FPS만 높다고 자연스럽다고 판정하지 않는다.
- 뒤집힘·NaN/Inf·백색 발산·지평선 앨리어싱·탭 복귀를 검사한다.
- 파도의 말림·비산수·공기 혼입까지 정확히 요구되면 높이장 범위를 벗어난다. SPH/FLIP/체적 또는 별도 쇄파 기하가 필요한 다음 범위다.
- 하얀 여백으로 사라지는 가장자리·공중 부표는 UI 연출층이다. 수면 물리와 분리하고 그 영역을 물리 검증 통계에 섞지 않는다.

## 13. 구현자에게 전달할 첫 작업 지시

> 색상·waterTone·카메라를 고정한 채 물리 기준 비교 경로를 만든다. 먼저 미터·초 단위를 정하고, 실제 파도 표면의 법선과 같은 광원에 대한 반사·투과를 구현한다. 현재의 seam/glow·법선 과장·반사 전용 광원을 독립적으로 끌 수 있게 한다. 이어 거품을 마루와 함께 새로 생기는 활성 성분과 물 위에 남는 잔류 성분으로 나눈다. 파도 속도로 잔류 거품 전체를 이동시키지 않는다. 이미 수정된 시간 정렬과 곱의 미분은 보존한다. 각 단계는 같은 상태 A/B와 수학 검증 결과를 남긴 뒤 다음 단계로 진행한다.

색상 때문에 어쩔 수 없다고 결론 내리기 전에, **같은 수면이 같은 시각·법선·빛·유속으로 계산되는지**부터 맞춘다.
