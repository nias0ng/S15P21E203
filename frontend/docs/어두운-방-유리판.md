# 어두운 방 · 유리판

향수 · 브랜드 · 노트 · 커뮤니티 화면이 쓰는 어두운 화면 구성입니다.
이 문서는 **작업을 시작하기 전에** 읽는 것이고, 코드에는 "그 자리를 고치면 바로
깨지는 것"만 한두 줄로 남겨 둡니다.

- 생김새 : `src/styles/scent-display.css`
- 켜는 자리 : `src/app/router/index.tsx` 의 `handle.night` → `src/app/layouts/RootLayout.tsx`
- 판 모양값 : `src/shared/ui/panel.ts` (`GLASS_PANEL` · `GLASS_PANEL_ASIDE`)

## 어느 화면이 어두운 방인가

| 화면 | 라우트 handle |
| --- | --- |
| A33 향수 목록 · A09 검색 결과 · A10 향수 상세 | `NIGHT` |
| A34 브랜드 목록 · 브랜드 상세 | `NIGHT` |
| A35 노트 목록 · A36 노트 상세 | `NIGHT` |
| A22a 후기 게시판 · A22b 자유 게시판 | `NIGHT` |
| A12 후기 상세 · A23 글 상세 · A24a · A24b 작성 | `TEXT_NIGHT` (폭 800) |

**서로 한 번에 넘어가는 화면끼리 묶습니다.** 상단 메뉴에서 옆으로 오가고, 목록의
한 줄을 누르면 상세로, [글쓰기] 를 누르면 작성 화면으로 갑니다. 한쪽만 밝으면 누른
순간 화면이 통째로 뒤집힙니다. 새 화면을 이 무리에 넣을지는 "여기서 한 번에
넘어가는가" 로 판단하세요.

## 어떻게 켜지는가

라우트에 `handle.night` 을 적으면 `RootLayout` 이 바깥 `<div>` 에 `.scent-night` 를
답니다. 그 안에서 **의미 토큰의 값만 다시 정의**합니다.

```
--color-surface · --color-ink · --color-ink-muted · --color-line ·
--color-line-soft · --color-surface-card · --color-danger
```

헤더 · 단추 · 입력칸이 전부 이 토큰을 쓰고 있어서 **컴포넌트는 하나도 안 고칩니다.**
화면마다 prop 을 다는 방식이었다면 헤더 · 드롭다운 · 로그인 단추를 각각 고쳐야
했습니다.

경로를 문자열로 맞춰보지 않고 라우트 `handle` 에 적는 이유: `/notes/:noteId` 는
라우트에 적힌 모양이고 실제 주소는 `/notes/5` 라, 경로 배열에 넣으면 **영영 안
걸립니다.**

## 층 세 개

```
어두운 방 (.scent-night)
└ 유리판 (.scent-glass · GLASS_PANEL)
  └ 카드 ([data-slot="card"])
```

- **머리 구역은 판 없이 어둠에 바로** 놓습니다. 판을 여러 장 쌓으면 층이 안 읽힙니다.
- **카드는 판보다 한 단 밝은 유리**이고, 카드 안쪽만 글자가 먹색으로 돌아옵니다.
- 판 위의 hover 는 **밝히지 않고 어둡게** 합니다. 글자가 밝은 쪽이라 바탕을 올리면
  둘이 가까워집니다(보조 글자가 4.5:1 을 지킬 여지가 알파 0.06 도 안 됨).
- 어둠 위에 놓이는 필터는 알약(`.scent-pill`)입니다.

`data-slot` 은 **화면 테마가 붙잡을 자리 이름**입니다(`Card` · `PerfumeCard` ·
`TileCard` · `rank` · `toast`). 컴포넌트는 자기가 어느 화면에 있는지 모르고, 이름만
달아 두면 각 화면의 CSS 가 자기 결에 맞게 덮습니다.

## 지키지 않으면 깨지는 것

아래는 **실제로 겪은 것**입니다. 코드에도 짧게 남겨 두었습니다.

1. **이 CSS 를 도메인 폴더로 옮기면 안 됩니다.** `features/perfume/` 에 두고 그
   도메인이 부르던 때, `features/brand` 는 `features/perfume` 을 import 할 수 없어
   (ESLint) CSS 가 아예 안 실렸습니다 — 향수 화면을 먼저 들렀다 오면 우연히 되고
   브랜드로 바로 들어오면 안 되는 버그였습니다. `main.tsx` 에서 한 번만 싣습니다.
2. **토큰 변수만 바꾸면 모자랍니다.** `color` 를 함께 적어야 합니다. `body` 가
   `text-ink` 로 정한 색은 거기서 이미 먹색으로 굳고, 자식은 변수가 아니라 굳은 색을
   물려받습니다. 이것 때문에 "검색어를 입력해주세요" 가 안 보였습니다.
3. **`<dialog>` 는 브라우저 기본 스타일이 `color: CanvasText`(검정)를 박습니다.**
   따로 적지 않으면 모달이 반쯤 지워진 채로 뜹니다.
4. **유틸리티 레이어가 `@layer components` 를 이깁니다.** 명시도로는 못 뒤집습니다.
   `border-radius` · `background-color` · 글자색처럼 Tailwind 유틸리티와 같은 속성을
   다투는 규칙은 **레이어 밖**(파일 아래쪽)에 둬야 합니다. 이걸 몰라서 카드가 안
   둥글어지고, 고른 알약이 흰 바탕에 흰 글자가 됐습니다.
5. **`--color-surface-sunken` 은 `.scent-night` 가 다시 정의하지 않습니다**(판
   안쪽에서만 뒤집힙니다). 어둠 위에 그냥 두면 아이보리 사각형이 남습니다 — 노트
   상세의 사진 칸, 브랜드 상세의 로고 판이 그랬습니다.
6. **투명 PNG 뒤는 토큰을 타면 안 됩니다.** 향수병 · 브랜드 로고는 배경이 투명이라
   상자 색이 그대로 비칩니다. 어두운 방에서 `bg-surface-card` 는 갈색으로 뒤집히고
   `bg-surface-sunken` 은 아이보리로 남습니다. `bg-white` 나 `bare` 를 씁니다.
7. **판 위에 입력칸을 올리면** `--color-surface-card`(방 값 `#362f26`)가 판보다
   어두운 갈색 덩어리가 됩니다. 판과 모달은 그 토큰을 검정 0.22 로 덮어 씁니다.

## 검색 알약이 토큰을 안 쓰는 이유

`SearchField` 는 색을 의미 토큰이 아니라 팔레트에서 직접 가져옵니다. 이 알약은
**어느 방에 있든 아이보리 종이 한 장**이라, 의미 토큰을 쓰면 어두운 방에서 같이
뒤집혀 버립니다.
