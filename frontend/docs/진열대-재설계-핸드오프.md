`src/assets/bottles/` 는 브랜드 공식 제품 사진이라 `.gitignore` 에 있습니다. 브랜치를 받아도 비어 있고,

- **가장 빠른 길:** 이 PC 의 `frontend/src/assets/bottles/` 폴더(PNG 156장, 투명 여백을 이미 잘라 둠)를

- **원본 zip 만 있다면:** 풀어서 같은 폴더에 넣고 투명 여백을 잘라야 합니다. removebg 원본은 1505x1360
  캔버스 가운데에 병이 폭의 40% 안팎으로 앉아 있어서, 자르지 않으면 병이 1/3 크기로 보입니다.
  아래 스크립트를 **저장소 루트에서** Windows PowerShell 5.1 로 한 번 돌리면 됩니다. 파일을 덮어씁니다.
- 파일 이름에 `features/shelf/api.ts` 의 `bottle('...')` 문자열(예: `Jo_Malone_London_-_Wood_Sage`)이
  들어 있어야 그 향수에 사진이 붙습니다.

```powershell
$src = @'
using System;
using System.Drawing;
using System.Drawing.Imaging;
using System.IO;
using System.Runtime.InteropServices;
public static class BottleTrim {
  // 알파가 0 이 아닌 픽셀의 경계 상자로 잘라 같은 파일에 덮어씁니다
  public static string Trim(string path) {
    int w, h, stride; byte[] buf;
    using (var bmp = new Bitmap(path)) {
      w = bmp.Width; h = bmp.Height;
      var d = bmp.LockBits(new Rectangle(0, 0, w, h), ImageLockMode.ReadOnly, PixelFormat.Format32bppArgb);
      stride = d.Stride; buf = new byte[stride * h];
      Marshal.Copy(d.Scan0, buf, 0, buf.Length);
      bmp.UnlockBits(d);
    }
    int minX = w, minY = h, maxX = -1, maxY = -1;
    for (int y = 0; y < h; y++) {
      int row = y * stride;
      for (int x = 0; x < w; x++) {
        if (buf[row + x * 4 + 3] != 0) {
          if (x < minX) minX = x; if (x > maxX) maxX = x;
          if (y < minY) minY = y; if (y > maxY) maxY = y;
        }
      }
    }
    if (maxX < 0) return "EMPTY";
    int cw = maxX - minX + 1, ch = maxY - minY + 1;
    if (cw == w && ch == h) return "unchanged";
    string tmp = path + ".tmp";
    using (var outBmp = new Bitmap(cw, ch, PixelFormat.Format32bppArgb)) {
      var od = outBmp.LockBits(new Rectangle(0, 0, cw, ch), ImageLockMode.WriteOnly, PixelFormat.Format32bppArgb);
      for (int y = 0; y < ch; y++)
        Marshal.Copy(buf, (minY + y) * stride + minX * 4, IntPtr.Add(od.Scan0, y * od.Stride), cw * 4);
      outBmp.UnlockBits(od);
      outBmp.Save(tmp, ImageFormat.Png);
    }
    File.Copy(tmp, path, true);
    File.Delete(tmp);
    return w + "x" + h + " -> " + cw + "x" + ch;
  }
}
'@
Add-Type -TypeDefinition $src -ReferencedAssemblies System.Drawing
Get-ChildItem frontend\src\assets\bottles -File -Filter *.png |
  ForEach-Object { "$($_.Name.Substring(0, 3)): $([BottleTrim]::Trim($_.FullName))" }
```

## 3. 진열대가 지금 어떻게 생겼나

### 3-1. 배치는 화면 폭에 따라 둘입니다

| 배치 | 화면 폭 | 모습 |
| --- | --- | --- |
| 한 장 배치 | 1024~ | 스크롤하지 않는 한 장. 벽 위 오른쪽에 상세 패널이 얹힘. 진열대 ↔ 내 컬렉션은 하단 띠 단추로 무대를 바꿈 |
| 쌓는 배치 | ~1023 | 벽을 화면 폭 가득 두고 그 아래로 페이저 · 상세 카드 · 내 컬렉션을 이어 세움. 페이지가 세로로 스크롤 |

- 가르는 곳은 `features/shelf/hooks/useShelfArrangement.ts` (`(width >= 64rem)`) 입니다.
- CSS 만으로 가르지 않습니다. 두 배치는 조각의 **자리**가 달라서, CSS 로 둘 다 그려 두고 하나를 숨기면 병 사진이
  든 벽이 두 벌 그려집니다.
- 1024 가 경계인 이유: 그보다 좁으면 상세 패널을 읽히는 크기(0.85 배)로 벽 위에 얹고 가리지 않는 병을 네 개 이상
  세울 수 없습니다. **패널을 더 줄여 억지로 한 장에 담지 않고 배치를 바꾸는 것이 이 화면의 원칙입니다.**
  (한때 패널을 0.43 배까지 줄였다가 글자가 5px 가 되어 되돌렸습니다.)

### 3-2. 한 장 배치 (1024~)

- 헤더 아래를 두 무대가 나눠 쓰고, 하단 띠 가운데 단추("내 컬렉션 ⌄" / "진열대로 ⌃")로 위아래로 바뀝니다.
- 진열대 무대: 제목 "나의 진열대" + 도구 줄(칩 · 드롭다운 · 검색) → 벽(상세 패널이 오른쪽 위에 얹힘) → 하단 띠(단추 · 페이저).
  부제 · 영문 문구 · 하단 문구 세 가지는 지웠습니다.
- 벽: 보유 중 · 시향해 봄 · 보유 희망이 **벽감을 하나씩** 갖고 가로로 이어집니다. 벽감 사이 벽에 분류 이름표("시향해 봄 17")가 붙습니다.
  - 휠을 굴리면 벽이 좌우로 흐르고, 멈추면 창 양 끝에 병이 걸리지 않게 칸 경계에 섭니다.
    굴린 쪽으로 다음 병이 12% 이상 들어와 있으면 그 병까지 들여 세웁니다. 마우스 휠 한 번 ≒ 병 한 칸.
  - 칩은 거르지 않습니다. 누르면 그 분류 첫머리로 흐르고, 창 가운데에 걸린 분류가 켜집니다.
  - 하단 페이저("1 / 25")는 세 분류를 벽 순서대로 이어 한 병씩 넘기고, 고른 병이 창 밖이면 벽이 따라갑니다.
  - 벽 양 끝 화살표는 마우스가 있으면 진열대에 올렸을 때만 보입니다(터치 · 키보드 포커스에서는 늘 보임).
- 크기는 고정값이 아니라 **남는 공간에서 계산**합니다(`lib.ts` 의 `shelfLayout` → `shelfMetrics`).
  화면 크기는 세로 스크롤 막대가 없다고 친 값입니다.

  | 화면 | 진열장 자리 | 벽감 | 병 | 칸 폭 · 창 전체 칸 / 가리지 않는 칸 | 상세 패널 폭 x 높이 · 배율 |
  | --- | --- | --- | --- | --- | --- |
  | 1920 x 1080 | 1800 x 800 | 605 | 420 | 225 · 8 / 6 | 340 x 605 · 1 |
  | 1920 x 950 | 1800 x 670 | 585 | 405 | 225 · 8 / 6 | 329 x 585 · 0.97 |
  | 1680 x 950 | 1560 x 670 | 530 | 370 | 195 · 8 / 6 | 298 x 530 · 0.88 |
  | 1440 x 900 | 1340 x 620 | 445 | 310 | 167.5 · 8 / 6 | 289 x 530 · 0.85(하한) |
  | 1440 x 780 | 1340 x 500 | 415 | 290 | 167.5 · 8 / 6 | 289 x 500 · 0.85 |
  | 1366 x 650 | 1266 x 460(최소 높이) | 375 | 260 | 140.7 · 9 / 6 | 289 x 460 · 0.85 |
  | 1024 x 768 | 944 x 488 | 400 | 280 | 157.3 · 6 / 4 | 289 x 485 · 0.85 |

  병 사진은 벽감 높이의 70% 입니다(4-1).

- **상세 패널** (9월 13일 오후)
  - 벽 위 오른쪽에 얹히고 윗선을 벽감에 맞춥니다. 벽은 패널 밑으로 이어지고, 패널이 아주 옅게 비쳐
    (`--panel` 알파 0.82 · 흐림 4px) 옆으로 병이 더 있다는 게 보입니다.
  - 안쪽 치수(여백 · 사진 · 글자 · 단추)는 1920 규격(폭 340 · 벽감 605)으로 적고, 작은 화면에서는
    `zoom: var(--panel-scale)` 로 **글자까지 통째로** 줄입니다. 배율 = 벽감 높이 / 605 를 **0.85 ~ 1** 로 묶습니다.
    0.85 에서 가장 작은 글자(12px)가 10px 남짓입니다.
  - 높이는 두 자리 중 하나입니다. 줄인 내용(560 x 배율)이 벽감에 들면 **벽감 높이**, 하한에 걸려 안 들면
    **벽감 + 매달린 이름표 자리(85)** 입니다. 그 사이 어정쩡한 자리에서 끝나지 않게 합니다.
  - 패널 폭은 DOM 에서 재지 않고 계산합니다. 패널이 좁아지면 가리지 않는 폭이 넓어져 벽감 높이가 바뀌고, 그 벽감
    높이가 다시 패널 폭을 정해서, 잰 폭으로 다시 셈하면 둘이 서로를 쫓아 오갑니다. `shelfLayout` 이 화면 폭에
    비례한 폭에서 시작해 네 번까지 맞춥니다.
  - 스크롤 막대는 만들지 않습니다. 내용이 더 길면 아래로 늘어납니다.
  - 벽이 흐르는 동안에는 패널 뒤 흐림을 끄고(패널 자리의 `data-moving`), 멈추면 200ms 에 걸쳐 되돌립니다(3-4).
  - 예전의 "창 높이 840 아래에서 사진 100 → 60 · 간격 10 → 5 · 최소 높이 500 해제" 규칙은 지웠습니다.
- **최소 높이 650** — 한 장 배치 전체(`h-[calc(100dvh_-_90px)] min-h-162.5`)가 이보다 낮아지지 않아 진열장 자리가
  460 아래로 줄지 않습니다. 1366 x 650 창에서는 페이지가 90px 스크롤됩니다. 벽 위의 휠은 벽이 받으므로 페이지
  스크롤은 벽 밖(제목 줄 · 하단 띠)에서 됩니다.
- **9월 13일 오전에 바뀐 것** (`d727505`)
  - **칸을 촘촘히** — 칸 폭 = 병 사진 높이 x 0.55(`SLOT_PER_BOTTLE`). 벽감 높이는 예전 셈 그대로입니다.
  - 칸 수를 두 가지로 셉니다 — `visible`(창 전체 · 창 밖 병 · 빈 벽 길이), `clear`(패널에 가리지 않는 칸 · 고른 병 들이기 · 벽 끝 ·
    칩 켜짐 · 오른쪽 화살표 자리).
  - 이름표 가장자리에 얇은 베벨(`.shelf-tag-bevel`) — 왼쪽 위 빛은 윗면이 옆면보다 밝고 모서리에서 멀어질수록 사그라지며,
    오른쪽 아래에 아주 얇은 그늘. 둘째 줄 이름에서는 앞에 붙은 브랜드를 뗍니다(`lib.ts` 의 `nameWithoutBrand`).
  - 벽감 입구 테두리까지 종이 결을 덮어 벽감 양옆의 흰 세로줄을 없앴습니다(4-2).
  - **벽 창(`.shelf-window`) 상자를 페이드 · 이름표 자리까지 넓혔습니다.** 예전에는 상자를 벽감 크기로 두고
    마스크만 `mask-clip: no-clip` 으로 상자 밖까지 그렸는데, 크롬이 상자 안팎을 따로 그려 상자 테두리 자리에
    1px 흰 줄(벽감이 창 왼쪽 끝을 지날 때 세로줄, 벽감 윗선에 가로줄)이 생겼습니다. "나의 진열대 왼쪽 흰 줄" 의
    진짜 원인이 이것이었습니다. 넓힌 상자는 pointer-events 를 끄고 안쪽 트랙만 켭니다.
  - 제목 줄 윗여백 60 → 40, 진열장은 제목 줄 바로 아래에 붙이고 남는 세로 공간은 하단 띠 위로 보냅니다.
    (다른 화면은 60 그대로라 진열대로 넘어올 때 제목이 20px 올라갑니다.)
  - 병이 한 화면을 못 채우는 분류(창 전체 칸 수 − 1 개 미만, 1920 에서 7개 미만) 뒤에는 빈 벽(`WallSection.gap`)을 둬서,
    그 분류 첫머리에서는 다음 분류가 화면에 — 패널 밑으로도 — 비치지 않습니다. 마지막 분류 뒤에는 두지 않습니다.

### 3-3. 쌓는 배치 (~1023, 태블릿 · 휴대폰)

- 위에서부터 제목 → 칩 · 드롭다운 줄 → 검색창 → 벽 → 페이저(오른쪽) → 상세 카드 → 내 컬렉션(제목 줄 + 카드 격자).
  하단 띠와 무대 전환(ShelfDeck)은 없습니다.
- 제목은 휴대폰 폭에서 활자 스케일 최대치(`text-display`, 28px), 768 부터 시안의 36px 입니다.
- 칩 · 드롭다운은 한 줄로 두고 넘치면 옆으로 밉니다(두 줄로 접으면 "벽의 세 칸" 이 한눈에 안 읽힙니다). 검색창은 그 아래 한 줄 전체.
- 벽은 화면 폭 가득, 진열장 자리 높이는 `clamp(380px, 72vw, 560px)` 입니다. 패널을 얹지 않아 창 전체가 가리지 않는 칸입니다.
  벽을 감싼 줄이 좌우 여백까지 넓히고 `overflow-x-clip` 으로 자릅니다 — 안 자르면 긴 벽이 페이지 가로 스크롤을 만듭니다.

  | 화면 | 진열장 자리 | 벽감 | 병 | 칸 폭 · 칸 수 |
  | --- | --- | --- | --- | --- |
  | 768 (태블릿 세로) | 708 x 553 | 465 | 325 | 177 · 4 |
  | 390 (휴대폰) | 350 x 380 | 280 | 195 | 116.7 · 3 |

- **손가락으로 끌기**(`useShelfFlow`): 가로로 8px(`DRAG_SLOP`) 넘게 끌면 끌기로 보고 트랙이 손가락을 그대로 따릅니다.
  떼면 뗀 속도 x 160ms(`FLING_MS`)만큼 더 흘러 칸 경계에 섭니다. 세로로 끌면 페이지가 스크롤됩니다(`touch-action: pan-y`).
  마우스 끌기는 받지 않습니다(병 누르기와 겹침). 끌고 뗀 뒤 병에 오는 click 은 버립니다.
  ⚠️ **아직 실제 터치 기기로도, 브라우저 터치 흉내로도 끌어 보지 않았습니다.**
- 상세 카드는 줄이지 않습니다(배율 1). **카드 폭**이 576 이상(`@container` 의 `@xl`)이면 얼굴(사진 180px · 이름 · 소개) |
  기록(향조 · 메모 · 조작) 두 단, 좁으면 한 단입니다. 화면 폭이 아니라 카드 폭으로 가릅니다.

### 건드리기 전에 알아야 할 것

- **이름표 벽도 병과 같은 한 칸 폭입니다.** 칸 폭이 전부 같아야 칸 단위로 멈추는 것만으로 창 양 끝에 병이 걸리지
  않습니다. 이름표 벽을 좁히면 두 벽감에 걸쳐 멈출 때 끝 병이 잘립니다.
- **병 칸(`.shelf-slot`)과 병 상자에 쌓임 맥락을 만드는 속성을 걸지 마세요**(z-index · transform · opacity · filter ·
  container-type). 병 그림자가 옆 병 위로 못 올라가고 multiply 도 섞이지 않습니다. 커지는 효과 · 투명도는 층마다 겁니다.
  이름표를 따로 합성 층으로 올리는 것(`will-change`)도 같은 이유로 안 됩니다 — 그 위에 겹친 병 층이 줄줄이 따라 올라갑니다.
- **창 밖 병을 전부 투명하게 지우지 마세요.** 페이드 구간 이웃 한 칸씩만 지웁니다(3-4). 전부 지우면 벽이 움직이는
  순간 한꺼번에 되살아나며 끊깁니다.
- **상세 패널 안쪽을 키울 때는 1920 에서 내용이 벽감(605) 안에 드는지 확인하세요.** 작은 화면은 같은 비율로 줄어서
  1920 만 맞으면 됩니다. 내용 높이를 크게 바꾸면 `lib.ts` 의 `PANEL_CONTENT`(560)도 함께 고칩니다.
- **패널 폭을 DOM 에서 재서 벽 계산에 넣지 마세요.** 폭과 벽감 높이가 서로를 쫓아 오갑니다(3-2).
- 창(`.shelf-window`)은 overflow 대신 **마스크 + clip-path** 로 가장자리를 지웁니다. `mask-clip: no-clip` 이면 크롬이
  마스크 이미지 바깥을 가리지 않아서, clip-path 로 페이드가 끝나는 바깥 경계를 잘라 둡니다.
- 무대(ShelfDeck)는 좌우 여백까지 넓혀 두었습니다(`-mx-[var(--gutter)]`). 벽이 여백 쪽으로 스며 나가는 페이드를
  본문 폭에서 자르지 않으려고서입니다. 쌓는 배치에서도 벽을 감싼 줄이 같은 이유로 여백까지 넓힙니다.
- 헤더 높이(90)를 바꾸면 `MyShelfPage` 의 `100dvh - 90px` 과 최소 높이 650(진열장 자리 460 이 되는 값)도 함께 바꿔야 합니다.

## 6. 확인할 때 주의

- Claude 앱의 브라우저 창은 문서가 `hidden` 으로 잡혀 `requestAnimationFrame` 이 멈출 때가 많습니다. 휠을 굴려도
  벽이 안 움직이면 코드보다 이것부터 의심하세요(`document.visibilityState` 확인). 그때는 콘솔에서 아래를 돌리면
  프레임을 대신 돌립니다 — 디버그 전용이고 새로고침하면 사라집니다.

  ```js
  const channel = new MessageChannel(); const queue = new Map(); let next = 0
  channel.port1.onmessage = (e) => { const cb = queue.get(e.data); if (cb) { queue.delete(e.data); cb(performance.now()) } }
  window.requestAnimationFrame = (cb) => { next += 1; queue.set(next, cb); channel.port2.postMessage(next); return next }
  window.cancelAnimationFrame = (id) => queue.delete(id)
  ```

- `hidden` 일 때는 `setTimeout` · `setInterval` 도 1초 단위로 늦춰집니다. **그 창에서는 프레임 속도 · 끊김을 잴 수 없습니다.**
  성능은 일반 크롬 창에서 봅니다.
- 같은 창의 스크린샷은 가끔 축소 비율이 틀려서 나옵니다. 창 크기를 흉내 낼 때(1440 · 1280 등) 특히 그렇습니다.
  치수는 `getBoundingClientRect` 로 재는 편이 정확합니다.
- 쌓는 배치처럼 페이지가 스크롤되는 화면에서는 세로 스크롤 막대만큼(약 15px) 폭이 줄어, 3장 표의 값과 조금 다르게 잽니다.
- 휴대폰 폭에서는 헤더가 넘쳐(4-5) 문서 폭이 화면보다 넓게 잡힙니다. 진열대 치수를 잴 때 이 점을 감안합니다.
