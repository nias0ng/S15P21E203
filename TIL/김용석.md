## 2026.08.31

## 자연어 향 표현 처리 방식 비교 실험

- 사용자가 입력한 자연어 향 표현을 실제 향수 데이터의 향조(Note)로 변환하기 위한 자연어 처리 방식을 실험했다.

- 기존 Rule 기반 방식, 규칙을 확장한 Extended Rule 방식, GPT-5.4-nano를 활용한 LLM 방식으로 동일한 평가 데이터를 처리해 결과를 비교했다.

- 각 방식의 Exact Match, Coverage, Scent F1, Avoid F1 등을 측정해 단순히 LLM을 사용하는 것이 아니라 기존 방식보다 실제 성능이 개선되는지를 확인했다.

## Stage 1 자연어 처리 모델 성능 평가

- Stage 1 실험 결과 Current Rule의 전체 Exact Match는 1.5%, Extended Rule은 4.5%, LLM 방식은 6.0%로 측정됐다.

- LLM 방식은 전체 입력의 41.5%를 처리했고 Scent F1은 64.2%를 기록했지만, 제외하고 싶은 향을 처리하는 Avoid F1은 0%로 나타나 명확한 한계가 있음을 확인했다.

- LLM API 호출은 200건 중 199건이 정상 처리됐으며, 응답 속도는 중앙값 약 1.74초, p95 약 3.19초로 측정해 정확도뿐만 아니라 실제 서비스 적용 시의 안정성과 응답 시간도 함께 확인했다.

## 자연어 처리 모델 개선 방향 결정

- 실험 결과를 바탕으로 기존 Rule 방식을 바로 제거하지 않고 이후 모델과 비교하기 위한 Baseline으로 유지하기로 결정했다.

- LLM이 일부 자연어 표현에서는 성능을 개선했지만 제외 조건 처리와 일부 회귀 사례가 존재해 LLM만으로 전체 자연어 처리를 해결하기 어렵다고 판단했다.

- 사용자 표현과 실제 Fragrantica 향조 데이터 사이의 의미적 차이를 연결하는 Semantic Bridge가 추가로 필요하다고 보고 다음 실험 방향을 정리했다.

## 2026.09.01

## Fragrantica 향조 데이터 정규화 분석

- Semantic Bridge를 구현하기 전에 Fragrantica에 존재하는 향조 이름 중 동일한 의미지만 서로 다른 이름으로 저장된 데이터를 우선 정리했다.

- 기존 Note vocabulary와 v0.3 분석 결과를 활용해 2,523개의 raw Note를 검토하고 2,492개의 canonical concept로 정규화하는 작업을 진행했다.

- 동일한 개념이라고 명확하게 판단할 수 있는 48개 향조 라벨을 30개 그룹으로 통합하고, 의미가 완전히 같다고 판단하기 어려운 항목은 임의로 합치지 않고 별도로 유지했다.

## Canonical Note 매핑 구조 설계

- 자연어 처리 결과가 데이터셋의 특정 표기 하나에만 연결되는 문제를 줄이기 위해 `사용자 표현 → Canonical Note → 실제 Fragrantica Raw Note` 구조를 설계했다.

- 동일한 개념으로 확인된 향조는 하나의 Canonical Note로 관리하되, 실제 향수를 검색할 때는 연결된 여러 Raw Note를 모두 검색할 수 있도록 매핑 방식을 정리했다.

- 반면 FAMILY, RELATED 관계처럼 비슷하지만 동일하지 않은 향조는 통합하지 않고 이후 Semantic Bridge에서 별도의 관계 정보로 사용할 수 있도록 구분했다.

## Semantic Bridge 적용을 위한 기반 데이터 구축

- 기존 Rule과 LLM이 처리하지 못했던 다양한 자연어 표현을 실제 향조 데이터에 연결하기 위해 Semantic Bridge Pilot을 다음 단계로 설정했다.

- 외부 향 지식을 무작정 추가하기보다 검증된 향조 데이터와 기존 분석 결과를 우선 활용하고, 자연어 표현과 Canonical Note 간의 매핑 성능을 측정할 수 있는 구조를 준비했다.

- 향후 동일한 Golden Set을 사용해 기존 Rule, LLM, Semantic Bridge 방식의 성능을 비교할 수 있도록 자연어 처리 파이프라인의 실험 구조를 정리했다.
