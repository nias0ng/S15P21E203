## 09/02 (수) — ERD 세부 구조 검토 및 기능 명세 보완
* 향수 데이터 모델링 구조 재검토
  * 동일 향수라도 Eau de Toilette, Eau de Parfum, Parfum 등 농도에 따라 노트·어코드·가격 정보가 달라질 수 있는 문제 확인
  * 향수명에 농도 정보를 포함하는 방식과 `concentration` 컬럼을 별도로 관리하는 방식 비교
  * 실제 향수 데이터셋 활용을 고려하여 향수 Entity의 식별 기준 및 데이터 중복·충돌 가능성 검토
* 사용자 진열대 및 컬렉션 관련 Entity 관계 구체화
  * `user_perfumes`, `collections`, `collection_perfumes`의 역할과 데이터 범위 재정의
  * 진열대에 저장된 향수만 컬렉션에 추가할 수 있다는 정책을 기준으로 Entity 간 1:N 및 N:M 관계 검토
  * 컬렉션을 타 사용자가 직접 조회하는 기능을 제거하고, 게시판에 공유된 컬렉션만 노출하는 구조로 정책 정리
  * 게시판에서 컬렉션을 선택하여 공유하는 흐름과 진열대에서 바로 게시판에 공유하는 흐름에 따른 DB 변경 필요 여부 검토
* 향수 가격 데이터 구조 세부 검토
  * `perfume_prices` 테이블의 `source` 컬럼 역할 확인
  * 가격 데이터의 출처와 수집 기준을 관리하기 위한 데이터 구조 점검
* 향 지도 탐색 기록 데이터 구조 수정
  * `map_exploration_logs`에서 불필요한 `map_version`, `action_type` 컬럼 제거
  * 사용자와 향수 정보를 중심으로 탐색 기록을 저장하도록 관계 구조 단순화
  * `users`, `perfumes`와의 비식별 관계 및 1:N 관계 기준으로 ERD 수정
* 향 지도 선택 타입 관리 구조 검토
  * 지도 내 선택 유형인 `pick_scent`, `pick_perfume`을 별도 타입 데이터로 관리하는 구조 검토
  * 기존 단순 `type` 컬럼을 FK 기반 코드 테이블로 분리하는 방식 설계
* AI 게시글 검수 데이터 저장 방식 재검토
  * 향수 후기 및 자유게시판 글 등록 시 게시 버튼을 누르는 시점에 AI 검수를 수행하는 사용자 흐름 구체화
  * 정책 위반 시 별도 보류 페이지로 이동하지 않고 작성 화면에서 즉시 모달로 사유를 안내하는 방식으로 정리
  * 검수 결과를 별도 `ai_content_review_results` 테이블에 영구 저장할 필요가 있는지 재검토
  * 실제 서비스에서 조회·이력 관리가 필요한 데이터와 요청 시점에만 사용되는 임시 처리 데이터를 구분하여 Entity 필요성 점검
* 기능 명세서 추가 작성 및 보완
  * **추천된 유사 향수 조회** 기능의 목적, 사전 조건, 사용자 동작, 시스템 처리, 정상 결과 및 예외 정책 정리
  * **회원 탈퇴** 기능 명세를 신규 작성하고 회원 탈퇴 시 필요한 사용자 흐름과 시스템 처리 항목 정리
* 기능 명세와 ERD 간 정합성 점검
  * 사용자에게 실제로 제공되는 화면 및 기능 흐름을 기준으로 기존 Entity와 컬럼의 필요성 재검토
  * 기능 변경으로 인해 불필요해진 데이터 구조와 새롭게 필요한 관계를 확인하며 ERD 세부 구조 보완

  * 하나의 자연어 입력이 추천 결과까지 이어지는 과정을 발표 슬라이드 단위로 재구성

  * 향수 탐색 과정에서 발생하는 정보 탐색 피로와 구매 후 향을 기억하지 못하는 문제를 사용자 시나리오로 구체화
  * 페르소나의 상황과 감정을 직관적으로 전달할 수 있도록 발표용 캐릭터 표정 및 이미지 자료 정리
* 프론트엔드 초기 세팅 및 개발 환경 구성
  * Vite + React 19 + TypeScript 6 기반으로 `frontend/` 프로젝트 초기 구성
  * 라우팅(React Router), 서버 상태(TanStack Query), 전역 상태(Zustand), HTTP(Axios), 스타일(Tailwind CSS) 등 핵심 라이브러리 선정 및 도입
  * Axios 인터셉터에서 토큰 주입, 에러 응답 정규화, 401 자동 로그아웃을 공통 처리하도록 구성
  * ESLint + Prettier 기반 코드 품질 도구 설정 및 `verify` 스크립트로 lint·타입 검사·빌드를 한 번에 확인하도록 정리
  * ESLint flat config 환경에서 일부 플러그인 설정 형식이 호환되지 않는 문제와 경로 alias 해석 문제를 확인하고 해결
* 프론트엔드 폴더 구조 및 협업 규칙 정리
  * 기능 명세서의 도메인 단위(인증, 향 지도, 향수, 추천, 컬렉션, 진열대, 커뮤니티)에 맞춰 `features` 기준 폴더 구조 설계
  * 도메인 간 직접 참조를 금지하고 공통 코드는 `shared`로, 화면 조합은 `pages`에서 처리하도록 규칙 정의
  * 팀원 간 실행 환경 차이를 줄이기 위해 lock 파일 커밋 및 설치·검증 절차 기준 정리

## 09/04 (금) — 커뮤니티·컬렉션 사용자 흐름 및 와이어프레임 구체화
* 커뮤니티와 사용자 컬렉션 간 순환 구조 정리
  * 다른 사용자의 컬렉션 조회 → 새로운 향수 발견 → 향수 탐색 → 내 진열대 등록 → 나만의 컬렉션 구성 → 커뮤니티 공유로 이어지는 사용자 흐름 구체화
  * 발견 → 기록 → 조합 → 공유가 반복되며 사용자의 향수 경험이 확장되는 서비스 구조 정리
