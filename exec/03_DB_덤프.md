## 1. 이 프로젝트의 DB 는 덤프 없이도 재현됩니다

향해는 **스키마와 데이터를 저장소에 넣어 두는 방식**을 씁니다. 덤프 파일이 없어도
아래 두 단계로 같은 DB 를 만들 수 있습니다.

```
스키마   Flyway 마이그레이션 26개 (V1 ~ V26)
         backend/src/main/resources/db/migration/
         애플리케이션이 기동할 때 자동으로 적용됩니다

데이터   시드 스크립트 7단계 + 원본 CSV
         backend/db/seed/
```

### 1-1. 스키마 — Flyway 마이그레이션

| | |
|---|---|
| 위치 | `backend/src/main/resources/db/migration/` |
| 개수 | **26개** (`V1` ~ `V26`, 결번 없음) |
| 처음 | `V1__init_schema.sql` |
| 최신 | `V26__correct_duplicate_perfume_identity.sql` |

별도로 로컬 시드 도구 전용 마이그레이션이 하나 있습니다 —
`backend/src/localSeed/resources/local-seed-migration/V1__create_seed_registry.sql`
(서버 JAR 에는 안 들어갑니다).

### 1-2. 데이터 — 시드 스크립트

`compose.manual-test.yaml` 의 `seed` 서비스가 아래를 순서대로 실행합니다.


## 2. 덤프를 뜨는 방법

### 2-1. 운영 DB 에서 (제출용 최신본)

배포 서버에서 실행합니다. **DB 컨테이너 이름과 계정은 운영 `compose.yaml` · `.env` 를 확인하십시오.**

```bash
# 스키마 + 데이터 전체 (평문 SQL)
docker exec -t <postgres_컨테이너> \
  pg_dump -U <DB_USER> -d <DB_NAME> --no-owner --no-privileges \
  > hyanghae_dump.sql

# 용량이 크면 압축 포맷
docker exec -t <postgres_컨테이너> \
  pg_dump -U <DB_USER> -d <DB_NAME> --no-owner --no-privileges -Fc \
  > hyanghae_dump.backup
```

`--no-owner --no-privileges` 를 붙이는 이유 — 복원하는 쪽의 DB 계정 이름이 다를 수 있어서
소유자·권한 구문을 빼 둡니다.

### 2-2. 로컬 수동 테스트 DB 에서

```bash
docker compose -f compose.manual-test.yaml up -d postgres
docker compose -f compose.manual-test.yaml run --rm seed

docker exec -t hyanghae-manual-test-postgres-1 \
  pg_dump -U hyanghae -d hyanghae_test --no-owner --no-privileges \
  > hyanghae_dump.sql
```

⚠ 컨테이너 이름은 `docker ps` 로 확인하십시오. compose 프로젝트명이
`hyanghae-manual-test` 라 접두사가 붙습니다.

## 3. 덤프를 복원하는 방법

```bash
# 평문 SQL
psql -U <DB_USER> -d <DB_NAME> -f hyanghae_dump.sql

# 압축 포맷
pg_restore -U <DB_USER> -d <DB_NAME> --no-owner --no-privileges hyanghae_dump.backup
```

⚠ **복원 뒤 Flyway 와 어긋나지 않게 주의하십시오.** 덤프에는 `flyway_schema_history`
테이블도 함께 들어갑니다. 덤프를 뜬 시점보다 마이그레이션이 늘어난 코드로 기동하면
Flyway 가 나머지를 이어서 적용합니다. 반대로 **덤프가 더 최신이면 기동이 실패**합니다.

## 4. 백지 상태에서 DB 를 만드는 가장 짧은 길

덤프 없이 처음부터 만들 때입니다.

```bash
cd S15P21E203
cp .env.example .env
```

`.env` 를 채운 뒤

```bash
docker compose -f compose.manual-test.yaml up -d --build --wait
docker compose -f compose.manual-test.yaml run --rm seed
```

- `up` 단계에서 백엔드가 기동하며 **Flyway 가 V1~V26 을 적용**합니다.
- `seed` 단계가 **향수·브랜드·노트·이미지·향 지도 데이터**를 넣습니다.

확인

```bash
curl http://localhost:8080/actuator/health
```

## 5. 담당자에게 확인이 필요한 것

```
[ ] 운영 DB 컨테이너 이름 · 계정 · DB 이름          (운영 compose.yaml / .env)
[ ] 제출용 덤프를 운영 기준으로 뜰 것인지, 시드 기준으로 뜰 것인지
[ ] 개인정보가 들어간 테이블을 덤프에 포함할 것인지
      users(이메일·비밀번호 해시) · nlr_unmatched_expressions(사용자 입력 원문)
      -> 제출물에 넣는다면 마스킹 또는 제외가 필요할 수 있습니다
```

⚠ **마지막 항목을 먼저 확인하십시오.** AI 미매칭 로그(`nlr_*` 표)에는 **사용자가 입력한
문장 원문**이 들어갑니다. 설문 실측에서 건강·신분 관련 서술이 있었습니다.
`ai/README.md` 의 「개인정보」 절에 같은 내용이 적혀 있습니다.
