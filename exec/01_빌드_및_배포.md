## 3. 빌드·배포 절차

### 3-1. 로컬 전체 실행

```bash
git clone <저장소 주소>
cd S15P21E203
cp .env.example .env
```

`.env` 값을 채운 뒤

```bash
docker compose -f compose.manual-test.yaml up -d --build --wait
docker compose -f compose.manual-test.yaml run --rm seed
```

프론트엔드는 따로 띄웁니다.

```bash
cd frontend
cp .env.example .env.local
npm ci
npm run dev
```

확인 주소

```
http://localhost:8080/actuator/health          백엔드
http://localhost:8080/swagger-ui/index.html    API 문서 (manual-test 프로필에서만)
http://localhost:5173                          프론트
```

자세한 절차는 `docs/local-development-guide.md` 에 있습니다.

### 3-2. 모듈별 빌드 명령

백엔드

```bash
cd backend
./gradlew clean assemble -x test --no-daemon
./gradlew test --no-daemon
```

프론트엔드

```bash
cd frontend
npm ci
npm run build
```

`npm run verify` 는 format → lint → typecheck → test → build 를 한 번에 돌립니다(MR 전 관문).

```bash
cd ai
python -m venv venv
venv/Scripts/python.exe -m pip install -r requirements.txt
```

### 3-3. 도커 이미지

```bash
docker build -t hyanghae-backend:latest backend
docker build -t hyanghae-ai:latest ai
```

⚠ **프론트엔드는 도커 이미지를 굽지 않습니다.** 정적 파일을 `rsync` 로 복사합니다.

### 3-4. CI/CD — Jenkins

`Jenkinsfile` 이 루트에 있습니다. `agent any` · `disableConcurrentBuilds()`.

| # | 스테이지 | 실행 브랜치 | 내용 |
|---|---|---|---|
| 1 | Checkout | 항상 | `checkout scm` |
| 2 | Backend Build | `develop` · `master` | `./gradlew clean assemble -x test` |
| 3 | Backend Test | `develop` · `master` | `./gradlew test` |
| 4 | Frontend Build | `develop` · `master` | `node:22-bookworm-slim` 에서 `npm ci && npm run build` |
| 5 | Docker Images Build | **`master` 만** | backend · ai 이미지 빌드 |
| 6 | Deploy | **`master` 만** | 배포 서버에서 `docker compose up -d` |
| 7 | Frontend Deploy | **`master` 만** | `frontend/dist` -> `rsync -a --delete` -> `/var/www/hyanghae/` |
| 8 | Backend Health Check | **`master` 만** | `curl --retry 12 --retry-delay 5` 로 `:8081/actuator/health` |
| 9 | AI Health Check | **`master` 만** | `docker inspect` 로 `hyanghae-ai` 헬스 상태 5초 × 12회 폴링 |

**즉 `develop` 은 빌드·테스트까지, `master` 병합이 곧 배포입니다.**

배포 대상은 Jenkins 에이전트와 같은 호스트이고, 이미지 레지스트리에 푸시하지 않습니다.

⚠ Jenkinsfile 에 `withCredentials` 호출이 없습니다. **비밀 값은 전부 배포 서버의
`.env` 에서 compose 가 읽습니다.**

## 4. 배포 시 특이사항

### 4-1. ⚠ 운영 `compose.yaml` 과 `.env` 는 저장소에 없습니다

배포 서버 `/home/ubuntu/hyanghae/` 에만 있습니다. Jenkinsfile 은 **그 두 파일의 존재를
검사만 하고 없으면 실패**합니다.

```
/home/ubuntu/hyanghae/compose.yaml   운영 서비스 정의 · 포트 매핑 · 볼륨
/home/ubuntu/hyanghae/.env           운영 DB 계정 · JWT_SECRET · GMS_API_KEY 등
```

**새 서버에 배포하려면 이 둘을 먼저 만들어야 합니다.** 인프라 담당에게 받으십시오.

### 4-2. ⚠ 업로드 볼륨을 반드시 붙이십시오

`/app/uploads` 는 이미지 내부 디렉터리라 **컨테이너를 다시 만들면 사라집니다.**
S3 를 끄고 서버 디스크를 쓸 때는 운영 compose 에도 볼륨이 있어야 합니다.

### 4-3. ⚠ AI 서버 로그 볼륨 소유자

AI 컨테이너는 비특권 사용자(`nlr`)로 돕니다. **bind mount 를 붙이면 호스트 디렉터리
소유자를 컨테이너의 `nlr` 과 맞춰야** 미매칭 로그를 쓸 수 있습니다. named volume 이면
Docker 가 소유자를 맞춰 줍니다.

### 4-4. ⚠ AI 서버 워커 수는 1로 두십시오

`--workers N` 을 붙이면 메모리가 그 배수로 늡니다. 워커마다 129,161 × 92 행렬
(약 162MB)을 따로 만듭니다. 요청 시간 대부분이 GMS 응답 대기라 워커를 늘려도 이득이 적습니다.

### 4-5. ⚠ AI 서버는 외부에 열지 마십시오

인증과 호출량 제한은 Spring 이 합니다. compose 에서도 `expose: 8000` 만 하고
호스트 포트를 공개하지 않습니다.

### 4-6. ⚠ AI 서버는 사전을 기동 시 한 번만 읽습니다

`load_index()` 가 기동 시 한 번만 돌고 사전 경로가 모듈 상수라,
**사전 파일을 바꿔도 돌고 있는 프로세스는 안 바뀝니다.** 반드시 재기동하십시오.

기동 로그로 확인합니다.

```
INFO:server:1단계 LLM 구조화 켜짐 (model=... prompt=...)
오타 검문소 켜짐 — 보호 낱말 654개
```

`/health` 의 `"llm"` 이 `true` 여야 LLM 구조화가 켜진 상태입니다.

### 4-7. ⚠ 배포 산출물이 커졌습니다

`ai/data/perfumes_nlr.csv.gz` 가 4.97MB 에서 **7.82MB (+57%)** 로 바뀌었습니다.
성별·계절·낮밤·노트 조건 기능이 이 파일을 다시 만든 결과입니다.

### 4-8. ⚠ `application-prod.yaml` 들여쓰기 — **백엔드 담당 확인 필요**

`server:` 아래에 `jpa:` 와 `flyway:` 가 들여쓰여 있어 실제로는 `server.jpa.*` ·
`server.flyway.enabled` 로 바인딩됩니다. 의도는 `spring.jpa` · `spring.flyway` 로 보입니다.

```yaml
server:
  forward-headers-strategy: ${FORWARD_HEADERS_STRATEGY:none}

  jpa:                      # spring.jpa 가 아니라 server.jpa 로 들어감
    open-in-view: false
    hibernate:
      ddl-auto: validate

  flyway:                   # spring.flyway 가 아님
    enabled: true
```

Flyway 는 클래스패스에 있으면 기본으로 켜지므로 마이그레이션 자체는 돌지만,
`ddl-auto` 와 `open-in-view` 는 Spring 기본값으로 동작할 가능성이 큽니다.

### 4-9. 오프라인·폐쇄망 시연 주의
